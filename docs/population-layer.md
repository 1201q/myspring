# 주민등록 인구·연령·세대 레이어

구현·확인일: 2026-11-15. `feature-population` 브랜치의 첫 버전이다.

## 사용 방법

지도 오른쪽 위 `지도 레이어`에서 `인구·세대`를 켠다. 오른쪽 아래 정보 패널에서 지표를 선택하고, 지도에서 읍·면·동을 누르면 인구·세대 수와 10세 단위 연령 분포를 확인한다. 기본 상태는 꺼짐이다.

| 지표 | 계산·단위 |
| --- | --- |
| 주민등록 인구 | 선택 월 말 인구, 명 |
| 세대 수 | 선택 월 말 주민등록 세대, 세대 |
| 20~39세 비중 | (20~29세 + 30~39세) / 전체 인구 x 100 |
| 60세 이상 비중 | 60~69세부터 100세 이상까지의 합 / 전체 인구 x 100 |
| 전월 대비 인구 증감 | 선택 월 인구 - 직전 달 인구, 명 |

재생 기간의 **마지막 월**과 인구 기준 월을 맞춘다. 3개월·12개월·누적을 선택해도 인구는 기간 합산이나 평균이 아니다. 업종 필터는 인구 통계에 영향을 주지 않으며, 시군구 필터는 해당 지역의 동만 표시한다. 동별 개폐업 증감도 켜져 있으면 배경색은 인구 레이어를 우선하고, 개폐업 점과 동별 정보 탭은 유지한다.

첫 버전의 제공 기간은 **2025-10 ~ 2026-10, 13개월**이다. 범위 밖 월은 최신 월로 대체하지 않는다. 첫 달의 전월 증감은 비교 자료가 없으므로 결측이다. 전체 인구가 0인 동의 연령 비중도 계산하지 않는다. 결측은 0과 다른 색상으로 표시한다.

인구·세대·비중은 파란색 강도로, 증감은 감소 주황·증가 청록으로 표시한다. 색상 범위는 현재 시도 또는 선택 시군구의 최대값을 사용하므로, 조회 조건 간 진하기를 직접 비교하지 않는다. 인구 수는 면적당 인구 밀도가 아니다.

## 원천과 수집

- 인구·연령: [행정안전부 행정동별 연령별 인구현황](https://jumin.mois.go.kr/ageStatMonth.do)의 `전체읍면동현황` CSV, 등록구분 전체, 연령 10세 단위.
- 인구·세대: [행정동별 주민등록 인구 및 세대현황](https://jumin.mois.go.kr/statMonth.do)의 같은 월·등록구분·조회 범위 CSV.
- [공공데이터포털의 연령별 인구 안내](https://www.data.go.kr/data/15097972/fileData.do)는 월간 갱신, 무료, 이용허락범위 제한 없음으로 안내한다. 이 안내는 포털의 해당 데이터에 대한 조건이며, 별도 원천·다른 통계로 일반화하지 않는다.
- 등록구분 전체는 거주자·거주불명자·재외국민을 포함하고 외국인은 제외한다. 세대는 인구총조사의 가구와 다르다. 60세 이상 비중을 65세 이상 고령인구 비중으로 부르지 않는다.

수집은 월별 두 CSV를 순차 요청한다. 원본은 Git 제외 경로 `data/population-source/`에 캐시한다. EUC-KR 디코딩 후 따옴표·천 단위 쉼표를 처리하며, 중복 코드·누락 컬럼·빈 숫자·연령 합계 불일치·두 원천 인구 합계 불일치가 있으면 발행을 중단한다.

```powershell
# 프로젝트 루트. Node.js 24 이상, 최초 수집에 공식 사이트 네트워크 접속 필요
node scripts/build-population.mjs

# 수집 기간 지정. 두 끝 월을 모두 포함
node scripts/build-population.mjs 2025-10 2026-10

# 프런트엔드에서도 기본 기간 재생성 가능
cd frontend
npm run build:population
```

사이트 다운로드 폼을 이용한 배치 스크립트이며 공개 REST API 계약은 아니다. 폼·CSV 구조 변경 시 검증에서 실패하도록 구성했다. 스크립트는 캐시를 자동 덮어쓰지 않는다. 원천 수정 공표를 반영하려면 해당 월 캐시를 별도로 교체한 뒤 재생성한다. 일반 프런트엔드 빌드는 외부 통계 사이트에 접속하지 않는다. 자동 월간 갱신 작업은 아직 연결하지 않았다.

## 경계 대응과 전국 범위

기존 SGIS/vuski 2026-10-01 행정동 경계를 사용하며, 서비스의 16개 재생 지역별로 자료를 분리한다. **10자리 행정기관코드가 같은 행만** 후보로 삼고 전체 명칭도 확인한다. 공백, 점·가운뎃점·쉼표 구분자, 번호 동의 `제`, 세종의 중복 중간 명칭처럼 확인된 표기 차이만 정규화한다. 이름만으로 코드를 추정하거나 폐지된 코드를 다른 동에 배정하지 않는다.

2026-10 기준 현재 경계 **3,559개 중 3,558개**에 대응한다. 서울은 427/427, 부산은 206/206이다. 평택시 고덕동 `4122066000`은 같은 코드의 통계 행이 없어 결측이다. 통계에만 존재하는 신설 동은 현재 경계에 없으면 표시하지 않는다. 이 대응률은 현재 경계 기준이며 원천 전국 인구의 포함률이나 과거 경계의 정확도를 의미하지 않는다.

과거 월은 행정구역 개편으로 대응 범위가 더 작을 수 있다. 화면에서 현재 지표의 표시 가능 동 수를 제공하며, 월·지역별 대응 수와 결측 코드는 [source.json](../frontend/public/data/population/source.json)의 `coverage`에 기록한다. 코드·이름의 일치만으로 과거 면적이 같았음을 보장하지 않으며 과거 경계는 복원하지 않는다.

## 구조와 성능

- `frontend/public/data/population/{regionId}.json`: 월 목록과 동별 인구·세대·11개 연령 구간의 배열. 결측은 `null`.
- `frontend/public/data/population/source.json`: 원천 주소·등록구분·연령 구간·수집 CSV와 발행 파일의 SHA-256·대응 현황.
- `usePopulation`: 레이어를 켤 때 선택 지역의 JSON과 경계를 병렬 조회. 지역 변경·토글 해제 시 요청을 취소하고 이전 지역 자료를 즉시 숨긴다. 조회 실패 시 재시도를 제공한다.
- `NationalPlayback`: 기존 deck.gl 오버레이에 면을 추가하므로 개폐업 점의 선택·상세 동작을 유지한다. 인구만 켜면 개폐업 공간배정 Worker를 추가로 실행하지 않는다.
- `PopulationPanel`: 기존 정보 독의 새 탭으로 지표 선택·범례·상세·원천 설명을 제공한다.

신규 DB 테이블이나 인증 키는 필요하지 않다. 발행 JSON은 프런트엔드와 함께 제공한다. 전국 파일을 브라우저에 한 번에 다운로드하지 않는다.

## 검증

```powershell
node --test scripts/population-source.test.mjs frontend/src/features/population/population.test.mjs
cd frontend
npm run build
npm run lint
```

원본 CSV 파싱·날짜 범위·명칭 표기 대응·코드 중복·숫자 결측을 검사한다. 발행한 모든 16개 지역의 해시, 월별 배열 길이, 연령 합계, 경계 버전, 대응 현황을 검사한다. 공식 다운로드에서 확인한 청운효자동 2026-10 인구 10,589명·4,824세대와 발행 결과도 비교한다.

실행 중인 로컬 서비스에서 인구 레이어 켜기, 서울 427개 동 표시, 쌍문3동 선택 상세, 2026-10에서 2026-09로 월 변경, 제공 기간 밖 2025-09 결측, 부산 전환 206개 동 표시, 연제구 필터 12개 동 표시를 확인했다. 실제 로컬 API와 발행 정적 데이터를 사용했으며, 모의 수치로 대체하지 않았다.

최종 검사: 신규 7개를 포함한 프런트엔드·수집 테스트 총 28개, 프로덕션 빌드, 린트, 변경 프런트엔드 파일의 Prettier 검사가 통과했다. 빌드에는 기존 500 kB 초과 청크 경고가 남아 있다. 브라우저 콘솔 오류는 없었고, 라이트·다크 모드와 세 정보 탭의 동시 활성화도 확인했다.

주민등록 인구는 유동인구·매출·창업 성공 가능성을 나타내지 않는다. 사업장 이벤트와 함께 탐색할 보조 지표다.
