# 전국 생활·상권 업종 서버 적재

2026-11-05 작업 기록. 적재 대상은 `commercial-area-v1` 15종이며, 이미 동일 원본이 반영된 약국을 제외한 14종을 순차 처리한다.

## 운영 방식

- 로컬 Java 적재기가 기존 SSH 터널을 통해 `permit_map_dev`에 저장한다.
- 원본 파일마다 다운로드한 한국 날짜를 `source_as_of`로 사용한다. 전체 자료가 동일한 날짜의 스냅샷이라는 뜻은 아니다.
- 기존 목재수입유통업과 학습용 테이블을 보존한다.
- `scripts/import-commercial-area.ps1`은 이번 작업 전용 실행 기록을 남긴다. 결과 파일의 완료 업종을 재개 시 건너뛴다. 실패한 DB 실행의 체크포인트 재개는 별도 `resume` 실행 ID 확인이 필요하다.
- 로컬 실행 시 테스트 컴파일과 적재를 동시에 실행하지 않는다. 이번 작업에서 겹친 컴파일 때문에 Java 메인 클래스 로딩이 실패했고, 완료 자료를 보존한 채 재실행했다. 재처리된 3개 업종은 신규·변경 없이 동일 건수로 확인됐다.
- 대량 전송을 위해 적재 CLI에 PostgreSQL JDBC `reWriteBatchedInserts` 옵션을 추가했다. DB 대상 제한 테스트 3개를 통과했다.
- 모든 행이 신규인 실행에서는 INSERT 때 이미 기록한 `last_seen_run_id`를 다시 MERGE로 갱신하지 않는다. 재수집 실행은 기존 갱신을 유지한다. 첫 적재·재수집의 최종 관측 실행을 검증하는 단언을 추가했으며 전체 H2 테스트 55개를 통과했다.
- 적재 중 회귀 테스트는 `test -x compileJava -x processResources`로 이미 컴파일된 main 클래스를 유지한 채 실행했다. 일반음식점 실행 전에 최신 main 클래스 컴파일은 완료된 상태였다.

비공개 권한으로 생성했고 `pg_restore --list`로 아카이브 목록을 확인했다. 이번 백업의 실제 복원 검증은 수행하지 않았다. 이전 단계의 백업은 별도 DB 복원 검증을 완료했다.

작업 전 디스크 여유 약 34GB, DB 크기 173,405,875바이트였다. Docker 재시작·설정 변경은 하지 않는다.

현재 지도/API는 기존 50건 샘플을 사용하므로 전국 원본 적재와 화면 연결은 별도 단계다.

## 중단 상태와 진단

일반음식점 실행 `798a2c62-1f68-4216-926f-ec6385fdaabd`는 최신 버전 연결 MERGE가 50분 이상 실행돼, 해당 PID·DB·계정·SQL을 확인한 뒤 쿼리만 취소했다. 완료된 다른 업종은 보존되며 일반음식점 publication 트랜잭션은 롤백됐다. 실행 상태는 `FAILED`, 처리 체크포인트는 2,309,440이다. 이 실행을 새 실행으로 중복 생성하지 않는다.

전체 15종 적재 완료가 아니다. 대상 14종의 합계는 1,770,359건이며 일반음식점 2,309,440건은 미반영 상태다. 기존 목재수입유통업 3,444건은 별도 보관한다.

확정한 병목 위치는 `current_version_id` 대량 MERGE이고, 실행 중 I/O 대기가 관측됐다. 별도 세션 EXPLAIN은 실행 중인 세션의 실제 계획·미커밋 통계를 그대로 보여주는 것이 아니므로 원인을 확정하는 근거로 사용하지 않는다. 외래키 검사와 접근 순서 등 세부 원인은 아직 분리 검증하지 못했다. '정상 처리 중'이라는 설명만 반복하며 대기한 운영 판단은 잘못이었다.

별도 `permit_map_verify_20261105_perf`에서 제한 시간 비교를 시도했으나 준비 INSERT가 45초 제한에 걸려 유효한 비교 측정값을 얻지 못했다. 이 임시 DB는 제거했다. 벤치마크 성공이나 성능 개선 완료로 표현하지 않는다.

취소 후 `national_permit` VACUUM은 완료했다. `national_permit_version` VACUUM은 180초 제한에 걸렸으며 오류 문맥은 물리 파일 끝부분 축소 단계였다. 정리가 전부 완료됐다고 단정하지 않는다. 원본/임시 스테이지는 삭제하지 않았다.

적재 CLI 전용 연결에 SQL 문장별 120초 제한과 단계별 진행 로그를 추가했고 전체 회귀 테스트 55개를 통과했다. 이는 재발 방지 장치이며 대량 성능 문제의 해결은 아니다. 대용량 재실행은 성능 검증 전까지 하지 않는다. 기존 컨테이너의 재시작·설정 변경은 수행하지 않았다.
