# 초기 지도 점 확대 현상 측정 — 2026-11-15

## 후속 수정과 검증

`interleaved:true`를 시험한 뒤 사용자가 점·경계선이 사라짐을 보고했다. 공유 모드는 되돌리고 `interleaved:false`를 유지한다. `onResize`로 받은 Deck 뷰포트 크기와 실제 지도 컨테이너 크기, 두 캔버스의 내부 해상도가 모두 일치하는 프레임의 `onAfterRender`에서만 점 캔버스를 표시하도록 수정했다. 고정 지연 시간과 private Deck API는 제품 코드에 사용하지 않는다.

수정 후 내장 Chromium(DPR 2, CSS 1280×720) 재측정은 `data-samples/startup-render/guard-timing-1/frames.json`에 있다. 표본 104개, 그리기 콜백 3회 중 초기 300×150 두 회는 모두 `visibility:hidden`이었다. 내부 해상도 2560×1440, Deck 뷰포트 1280×720이 된 정상 프레임은 `visibility:visible`이었다. 잘못된 크기로 노출된 그리기 콜백은 0회였다. 실제 화면에서도 점과 서울 경계선이 표시됨을 확인했다. 이는 해당 실행에 대한 검증이며 모든 브라우저 조합을 시험한 것은 아니다.

임시 계측 연결을 제거한 최종 소스로 `npm run build`와 `git diff --check`를 통과했다. 아래의 '변경 상태'는 최초 진단 시점의 기록이다.

실행 중인 localhost:5173 서비스와 실제 서울 데이터로 점 캔버스의 초기 크기 불일치를 재현했다. 점 캔버스가 내부 300×150, Deck 뷰포트 300×150인 상태에서 CSS 1063×703으로 표시된다. 이후 내부 2126×1406, Deck 뷰포트 1063×703으로 바뀐다(DPR 2). 작은 캔버스의 점·경계가 큰 화면으로 늘어나 흐려지고 위치가 어긋나는 현상이다.

## 측정 방식과 범위

- Codex 내장 Chromium 브라우저에서 실제 서비스에 접속. 사용자 Whale 창은 자동화 연결이 실패해 직접 측정하지 못했다. 따라서 아래 시간은 Whale 원본 녹화의 시간이 아니다.
- `requestAnimationFrame` 및 Deck `onAfterRender`에서 시각, MapLibre 중심·줌·캔버스 크기, Deck 뷰포트·캔버스·drawing buffer 크기, 레이어와 필터를 기록했다.
- 3회 실행, 총 455개 표본. 표본은 RAF와 그리기 콜백을 합친 것이며 455개의 서로 다른 화면 프레임이라는 뜻은 아니다.
- timing 실행에서는 이미지 readback을 하지 않았다. capture 실행에서만 점 캔버스를 `toDataURL`로 저장했다. RAF 및 GL 상태 조회 등의 계측 부하는 남아 있다.
- 시각은 페이지 탐색 시작 기준 `performance.now()` ms이다. 네트워크·CPU 제한은 따로 설정하지 않았다. timing-1과 나머지 실행은 내장 브라우저 패널 크기가 달라 직접 속도 비교 대상으로 사용하지 않는다.

## 코드와의 연결

`NationalPlayback.tsx`는 `MapboxOverlay({interleaved:false})`로 지도 위에 별도 캔버스를 생성한다. 설치된 `@deck.gl/mapbox/src/mapbox-overlay.ts`의 `_onAddOverlaid`는 Deck 생성 뒤 컨테이너 크기를 지정하고, `onAdd`가 반환한 컨테이너는 MapLibre가 지도 DOM에 붙인다. Deck/luma의 크기 관찰·반영과 GPU 초기화는 비동기로 진행된다. 측정에서 그 크기 반영 전에 데이터가 준비되면 기본 300×150으로 점이 그려지는 것이 확인됐다.

지역 맞춤 `fitBounds`의 600ms 애니메이션은 함께 실행되지만, 그리기 시점의 지도와 Deck 중심·줌은 일치했다. 점 크기와 위치가 크게 변하는 현상의 직접적인 재현 근거는 캔버스·뷰포트 크기 불일치다.

## 변경 상태와 후속 수정 방향

측정용 import·콜백·Vite 미들웨어 연결은 모두 제거해 서비스 소스를 원상 복구했다. 기능 수정은 하지 않았다. 기존 성능 점검 문서·벤치마크는 수정하지 않았다. 실제 브라우저 계측만 수행했으며 제품 코드 변경이 없어 별도 빌드·테스트는 실행하지 않았다.

수정 시에는 캔버스 CSS 크기와 Deck 뷰포트·내부 해상도가 일치하기 전에 점을 노출하지 않도록 초기화를 정리하거나, 공유 캔버스 방식(`interleaved:true`)을 검토할 수 있다. 어느 방식이든 동일 계측으로 초기 잘못된 크기의 점 출력이 사라지는지 확인해야 한다.

임시 계측 소스는 사용자 요청으로 삭제했다. 측정 결과와 캡처만 보관한다.
