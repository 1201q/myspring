# 개·폐업 변화 지도: 데이터셋 및 DB 설계안

작성일: 2026-11-03. 최신 사용자 설명을 반영한 설계 제안이며 DB 마이그레이션을 실행한 것은 아니다.

2026-11-04: [전국 원천 실검증](national-data-source-audit.md)에서 일반음식점·미용업·노래연습장업 전체 CSV 총 2,834,872건을 확보했다. 아래의 데이터 가용성 미확인 항목 중 3종 전국 CSV 다운로드와 과거 폐업 포함 여부는 확인됐으며, 과거 자료 완전성·변경 API 실호출·좌표 정확도는 추가 검증 대상이다.

같은 날 [전체 업종 카탈로그](national-category-catalog.md)를 확보했다. 공식 현재 메뉴의 인허가 업종은 195종이며 기타/보조 정보 13종은 개폐업 집계에서 분리한다. 195종 중 9종에는 폐업일 필드가 없으므로 업종별 이벤트 지원 범위가 달라야 한다. 수집 대상은 카탈로그로 관리하며 현재 3종 검증을 전체 서비스 범위로 제한하지 않는다.

후속으로 공통 인허가·관측 버전·사건·청크 적재를 구현하고, [PostgreSQL 실검증 및 서버 반영](national-postgres-import.md)으로 약국·목재수입유통업 74,214건을 저장했다. 공간 테이블·집계·새 조회 API 연결은 아직 별도 단계다.

## 목적과 집계 단위

전국 복수 업종의 인허가 발생·종료와 영업 지속 추정을 시간에 따라 지도에서 재생한다.
음식점은 첫 검증 대상이며 최종 수집 범위가 아니다. 시간은 원천이 제공하는 날짜 기준으로 일/월/연도 단위를 지원한다. 시간대별(시·분) 개·폐업은 날짜만 있는 원천으로 복원하지 않는다.

- 개업 표시는 인허가일 기반 대리지표이고 실제 영업 개시와 동일하다고 단정하지 않는다.
- 기본 집계 단위는 점포가 아니라 인허가 건이다. 한 점포의 복수 업종 허가는 서로 다른 건이다.
- 지도는 개업·폐업 발생과 영업 추정 재고를 분리한다. 단일 쇠퇴 점수는 초기 범위에 넣지 않는다.
- LOCALDATA 대상 업종만 다루므로 모든 상점/사업체를 포괄한다고 표현하지 않는다.
- 현재 50건은 의도적으로 선택한 품질 검증 샘플이다. 개폐업률이나 상권 추이의 근거로 사용하지 않는다.

## 데이터셋 구성 및 검증 관문

| 데이터 | 역할 | 확보/검증할 내용 |
| --- | --- | --- |
| LOCALDATA 계열 전국 업종별 인허가 전체 자료 | 과거 인허가·폐업과 현재 상태의 기반 | 공식 파일/API 경로, 과거 폐업 포함 기간, 전국 지역 완전성, 업종 코드, 관리번호, 좌표계, 이용 조건 |
| 업종별 변경 자료 또는 변경 조회 API | 일일 변경·소급 정정·결손 수집 | 변경 기준시각 의미, 제공 시작일, 페이지 안정성, 삭제/이관 의미, 호출 제한 |
| 공간 기준 데이터 | 동일 영역의 시간 비교 | 고정 격자 정의 또는 상권/행정동 경계의 출처·버전·유효기간 |
| 상권 점포·추정매출·인구 통계 (후속) | 인허가 감소와 경제활동 약화를 구분 | 지역/업종/기간 단위와 제공 범위가 맞는지, 기존 자료와 중복 집계되지 않는지 |

첫 검증 후보는 일반음식점·미용업·노래연습장업이다. 업종별 공식 실파일/응답을 확보한 뒤 최종 선정한다.
생활밀착 업종부터 시작하고 지도상의 주소가 영업 장소를 대표하지 않는 업종 등은 별도 표시/제외 정책을 마련한다.
각 업종에서 현재 영업뿐 아니라 과거 폐업 행도 확보해야 한다. 지역별 연도별 건수와 좌표/날짜 누락률을 비교하고 신뢰 가능한 재생 시작 연도를 정한다.

오픈체크의 일일 전량 덤프 + API 보완 방식은 참고 서비스의 운영 설명이다. 우리 수집 경로의 이용 가능성을 검증한 결과가 아니다.
동 사이트의 최근 1년 폐업 상세 제공도 원천의 보관 제한으로 단정하지 않는다. 이 서비스는 장기 재생을 위해 확보한 과거 폐업과 향후 변경 이력을 계속 보존하는 방향이다.

필수 원천 항목: 업종 식별 코드, 기관 코드, 관리번호, 상호, 인허가일, 폐업일, 일반/상세 상태 코드·명칭, 주소, 원천 X/Y, 좌표계 근거, 원천 수정시각, 자료 기준일.
수집일과 원천 수정시각을 개업/폐업 발생일로 대신 사용하지 않는다. 누락일은 NULL과 품질 사유로 남긴다.

## 논리 테이블

PostgreSQL + PostGIS를 목표로 한다. 현 서버에 PostGIS가 설치됐다고 가정하지 않으며, 기존 Docker 서비스를 변경하지 않고 도입 방식을 별도 검증한다.

| 테이블 | 주요 필드/키 | 역할 |
| --- | --- | --- |
| `permit_category` | id, source_system, source_type_code, name, display_group | 원천 업종 분류. 일반음식점 안의 한식/중식 같은 업태와 구분 |
| `source_dataset` | id, category_id, endpoint_or_file_url, coverage_region, declared_crs, license_note, schema_version | 자료 출처/수집 계약. API와 파일이 같은 허가를 제공하는지 매핑 |
| `import_run` | id, dataset_id, status, source_as_of, started_at, finished_at, checkpoint, counts, error_summary | 수집 성공/실패, 기준일, 재개 위치, 품질 통계 |
| `source_file` | id, run_id, uri, sha256, downloaded_at, row_count, schema_version | 압축 원본 파일과 무결성. DB에는 메타데이터, 파일은 별도 저장소 |
| `permit` | id, source_system, category_id, municipality_code, management_number, first_seen_at, last_seen_at, current_version_id | 인허가의 안정된 내부 식별자 |
| `permit_version` | id, permit_id, run_id, observed_at, source_updated_at, content_hash, name, addresses, permitted_on, closed_on, raw_status/code, normalized_status, source_x/y/crs, geom, location_basis, quality_flags, raw_reference | 관측한 내용의 변경 이력. 동일 내용 재수집은 버전을 추가하지 않음 |
| `permit_event` | id, permit_id, event_type, event_date, date_basis, geom, location_basis, derived_from_version_id, is_current, superseded_at | 현재 채택된 인허가/폐업 이벤트와 소급 정정 흔적 |
| `analysis_area` | id, kind, code, version, valid_from/to, geom | 고정 격자 또는 버전 있는 상권/행정동 경계 |
| `area_monthly_metric` | area_id, area_version, category_id, month, permit_open_count, permit_close_count, active_estimated_start/end, excluded_counts, coverage_status, build_id | 지도 저배율 표시 및 월별 재생용 재생성 가능한 집계 |

`permit` 식별 후보는 `(source_system, category_id, municipality_code, management_number)`이며 업종별 실데이터에서 관리번호의 유일 범위와 이관 동작을 확인한 후 확정한다.
2026-11-04 전량 검사에서 노래연습장업 관리번호 단독 중복은 60,917행이고 기관코드+관리번호 중복은 0행이었다. 따라서 기관코드를 생략한 관리번호 전역 유니크 키를 사용하면 안 된다. 상세는 전국 원천 실검증 문서를 따른다.
파일/API/서울 중복 수집은 출처 간 대응표로 연결하고, 주소/상호만으로 다른 허가를 병합하지 않는다.
raw는 허용된 필요한 필드와 원본 파일 위치를 보관한다. 불필요한 개인정보는 적재 대상에서 제외한다.

### 사건의 날짜와 관측 날짜

예: 2020-03-01 인허가, 2023-08-10 폐업한 행을 2026-11-03 처음 수집했다면:

- OPEN 사건 날짜: 2020-03-01, 근거: 원천 인허가일
- CLOSE 사건 날짜: 2023-08-10, 근거: 원천 폐업일
- 해당 행을 관측한 날짜: 2026-11-03

2026년에 수집했다는 이유로 사건을 2026년 지도에 표시하지 않는다.
이후 폐업일이 2023-09-10으로 정정되면 이전 버전/이벤트를 보존하고 채택 이벤트를 교체한다. 영향받는 월과 이후 재고 집계를 재계산한다.
상태 변경/휴업/재개업은 원천이 유효 날짜를 제공할 때만 해당 날짜의 사건으로 만든다. 스냅샷 비교만으로 발견하면 관측 변화로 기록하며 정확한 발생일은 미상이다.

### 과거 위치

`geom`은 SRID 4326 Point이며 원천 좌표와 변환 근거를 함께 저장한다. 업종/출처마다 좌표계를 검증하며 현재 구로구용 EPSG:5174를 전국에 일괄 적용하지 않는다.
과거 위치 이력이 없으면 최신 좌표에서 과거 사건을 표시하는 근사임을 명시한다 (`location_basis=LATEST_KNOWN`).
수집 후 주소/위치 변경은 버전으로 보존하지만 변경 관측일을 실제 이전일로 간주하지 않는다. 실제 유효일을 모르면 과거 위치를 확정하지 않는다.

### 인덱스 및 일관성

- `permit` 원천 식별 유니크 키, `permit_version(permit_id, observed_at)` 인덱스.
- `permit_version.geom`, 채택된 `permit_event.geom`에 GiST 공간 인덱스.
- 이벤트 날짜/유형과 permit/category 조회를 위한 인덱스는 실쿼리 EXPLAIN 후 선정.
- OPEN/CLOSE가 각 하나인 현재 모델에서는 permit+event_type에 채택 이벤트가 하나만 존재하도록 부분 유니크 제약. 재개업 주기가 확인되면 episode_id를 추가해 제약 변경.
- 수집/변환이 검증 완료된 run만 공개한다. 부분 적재나 누락 페이지를 영업 감소로 집계하지 않는다.
- 파일에서 사라진 행을 폐업/삭제로 추정하지 않는다. 명시된 종료와 이관 규칙을 구분한다.
- 집계 build_id를 통해 같은 완료된 빌드의 월별 프레임을 제공한다. 소급 정정 전후가 한 번의 재생에 섞이지 않게 한다.

## 재생 및 지표의 정의

월별 사건은 `[월 시작, 다음 월 시작)` 기준이다. 인허가일/폐업일이 같은 건도 각 사건에 기록하되 하루 말 영업 추정 수에는 포함되지 않을 수 있다.

- `OPEN`: 기간 내 원천 인허가일이 있는 허가. 초록색으로 강조.
- `CLOSE`: 기간 내 원천 폐업일이 있는 허가. 주황색으로 강조 후 다음 프레임에서 제거.
- `ACTIVE_ESTIMATED(t)`: `permitted_on <= t AND (closed_on IS NULL OR closed_on > t)`를 만족하는 날짜 기반 영업 추정. 휴업/취소 이력 미상은 별도 표시.
- 원천 현재 상태는 별도 필드다. 현재 폐업 상태인데 폐업일이 없는 건은 과거 영업을 확정할 수 없으므로 불확실 건수를 표시한다.
- 최초 프레임은 시작일 전부터 존재한 허가의 기준 재고가 있어야 한다. 기간 내 OPEN/CLOSE만 모아서 0부터 재생하지 않는다.

영역·업종·원천 범위가 고정됐을 때 `순증감 = OPEN - CLOSE`, `월초 대비 감소 비율 = (월말 추정 수 - 월초 추정 수) / 월초 추정 수`를 표시한다. 분모 0이면 비율은 NULL.
휴업/재개업/이관 등을 포함한 실제 상태 재고는 OPEN-CLOSE만으로 맞지 않을 수 있다. 완전한 상태 이력이 없으면 추정이라는 이름을 유지한다.
지도 위치가 있는 사건 수와 지역 코드로만 집계 가능한 사건 수를 구분한다. 좌표 없는 건을 지도 특정 격자에 임의 배치하지 않는다.

비교에는 동일 업종 묶음·동일 공간 경계·동일 수집 범위를 유지한다. 격자 크기/상권 경계는 버전을 기록한다.
전년 동월 및 최근 3/6/12개월 추세를 함께 본다. 폐업 수가 많아도 점포 총수가 많거나 교체가 활발한 지역일 수 있으므로 단일 수치로 쇠퇴를 확정하지 않는다.
최근 기간은 신고/공개 지연으로 불완전할 수 있어 잠정치와 자료 기준일을 표시한다.

저배율에서는 격자/상권 집계와 클러스터, 고배율에서는 bbox+기간+업종으로 제한된 실제 사건/추정 영업 위치를 내려준다.
초기 기준 재고와 기간 이벤트를 나누어 요청하고 프레임별 전체 전국 마커를 다시 내려주지 않는다. 큰 범위는 집계로 전환하고 누락된 제한 결과로 통계를 계산하지 않는다.

## 실행 순서

1. 후보 3개 업종의 공식 전체 파일/변경 경로 및 과거 폐업 포함 범위를 실물로 확인한다.
2. 각 업종에서 영업/과거 폐업/주소 변경/날짜·좌표 누락 샘플을 비교한다. 데이터 가용 범위 보고서를 만든다.
3. 식별 키·상태 매핑·좌표계 계약을 확정하고 신규 스키마 마이그레이션을 작성한다. 기존 샘플과 학습용 restaurants를 보존한다.
4. 한 지역의 3개 업종을 전체 적재하여 재시도/중복 방지/소급 정정과 완전성 검증을 구현한다.
5. 월별 사건·시작 재고·집계 API를 만들고 지도 재생을 붙인다.
6. 검증된 업종을 전국으로 확대하고 이후 다른 업종을 어댑터로 추가한다.

기존 permit_businesses는 원천 최신값을 저장한 첫 실습이다. 과거 변경 이력이나 여러 업종의 보편적인 좌표계를 이미 갖춘 것으로 취급하지 않는다.

## 확인한 참고 자료

- 기존 원천 실응답 조사: [data-source-audit.md](data-source-audit.md). 구로구 한 업종의 샘플 검증이며 전국/복수 업종 완료가 아님.
- [오픈체크 출처 안내](https://inhu.kr/sources): 해당 서비스의 수집 방식 및 제공 정책.
- [오픈체크 상태 안내](https://inhu.kr/status): 인허가 건 단위와 원천 상태 표기의 차이.
- [서울시 상권분석서비스 소개](https://golmok.seoul.go.kr/introduce.do): 점포, 추정매출, 인구, 공간 영역 등 보완 지표 후보. 서울 자료를 전국 자료로 표현하지 않음.

전국 공식 원천의 현재 전체 덤프 다운로드 가능 여부, 과거 자료 기간, 신규 업종의 실제 API 응답은 추가 검증이 필요하다. 아직 확보하지 않은 데이터나 전체 수집 성공을 주장하지 않는다.
