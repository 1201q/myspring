# 일반음식점 원천 데이터 검증 - 1차

조사일: 2026-11-03 (KST)

## 결과와 범위

첫 학습 대상은 **서울특별시 구로구 일반음식점**으로 선정했다.
공식 서울 열린데이터광장의 공개 Sheet 응답 1,000건을 분석하고 서비스에 필요한 필드만 추린 실제 샘플 50건을 저장했다.
DB 적재, Entity 변경, Flyway 변경, 서버 작업은 수행하지 않았다.

전국 확장 후보인 행정안전부 API는 공식 페이지에 게시된 Swagger 명세를 확인했다.
이번 작업에서는 인증키를 사용하는 전국 API 호출은 수행하지 않았다.
따라서 **서울 실응답 관찰**과 **전국 API 명세 확인**을 구분한다.
이 문서는 1개 업종의 1차 조사이며, 기획서 Task 0 전체의 3개 업종 검증을 완료한 것은 아니다.

현재 서울시 페이지의 원본시스템 링크는 전국 API인 `15154916`으로 연결된다.
기존 `localdata.go.kr` 홈페이지는 이번 도구의 접속 시도에서 시간 초과가 발생했다. 서비스 종료 여부는 판단하지 않았다.

## 샘플과 재현 정보

- [실제 샘플 50건](data-samples/guro-restaurants.sample.json)
- [1,000건 분석 통계](data-samples/guro-restaurants.quality.json)
- [출처, 요청 파라미터, 선택 방식, SHA-256](data-samples/guro-restaurants.provenance.json)

공식 페이지가 사용하는 `POST /dataList/dataView.do` 공개 미리보기 요청을 재현했다.
`infId=OA-18668`, 기관코드 `3160000` 등 파라미터는 해당 페이지의 공개 폼 값을 그대로 사용했다.
원본 응답의 `page.totalCount`는 19,756이지만 실제 분석한 행은 반환된 **첫 응답 1,000건**이다.
페이지의 미리보기 노출 제한은 1,000건이다. 페이지 수 메타데이터가 있다는 이유로 전체 수집 API라고 간주하지 않는다.

저장 샘플은 영업 20건, 폐업 20건, 좌표 누락 10건, 도로명주소 누락 10건을 각 조건에서 먼저 선택한 후 관리번호로 중복 제거하여 50건이 되었다.
무작위 표본이나 구로구 전체를 대표하는 통계 표본이 아니다.
선택한 필드의 원본 문자열과 빈 문자열을 유지했다. 전화번호, 인원, 보증액, 월세 등 서비스와 무관한 필드는 저장하지 않았다.
전국 API 응답으로 가장하거나 임의 데이터로 빈 값을 채우지 않았다.

공개 웹 미리보기는 이번 검증에 사용한 수단이다. 정기 수집에 사용할 안정된 공식 API 계약으로 확정하지 않았다.

## 주요 필드 비교

전국 열은 명세상의 이름이고, 서울 열은 실제 응답에서 확인한 이름이다.
명칭의 대응은 확인했지만 두 시스템의 모든 값이 같다는 교차 대조는 아직 하지 않았다.

| 의미 | 서울 Sheet 실응답 | 전국 API 명세 | 확인 결과 |
| --- | --- | --- | --- |
| 자치단체코드 | `OPNSFTEAMCODE` | `OPN_ATMY_GRP_CD` | 서울 응답 1,000건 모두 `3160000` |
| 관리번호 | `MGTNO` | `MNG_NO` | 서울 예: `3160000-101-1996-01852`; 숫자가 아닌 문자열로 보존 |
| 사업장명 | `BPLCNM` | `BPLC_NM` | 서울 샘플에서 확인 |
| 인허가일 | `APVPERMYMD` | `LCPMT_YMD` | 서울 `yyyy-MM-dd`; 전국 명세 `YYYYMMDD` |
| 폐업일 | `DCBYMD` | `CLSBIZ_YMD` | 서울 빈 문자열 또는 `yyyy-MM-dd`; 전국 명세 `YYYYMMDD` |
| 영업상태코드/명 | `TRDSTATEGBN`, `TRDSTATENM` | `SALS_STTS_CD`, `SALS_STTS_NM` | 아래 관측 코드 참조 |
| 상세상태코드/명 | `DTLSTATEGBN`, `DTLSTATENM` | `DTL_SALS_STTS_CD`, `DTL_SALS_STTS_NM` | 일반 상태와 별도 보관 필요 |
| 지번주소 | `SITEWHLADDR` | `LOTNO_ADDR` | 도로명주소 누락 시 표시 대안 |
| 도로명주소 | `RDNWHLADDR` | `ROAD_NM_ADDR` | 서울 응답에 빈 문자열 존재 |
| 업태 | `UPTAENM` | `BZSTAT_SE_NM` | 일반음식점 안의 세부 업태; 원천 업종 분류와 구분 |
| 좌표 X/Y | `X`, `Y` | `CRD_INFO_X`, `CRD_INFO_Y` | 서울 실제 숫자 문자열 또는 빈 문자열 |
| 최종수정시점 | `LASTMODTS` | `LAST_MDFCN_PNT` | 서울 `yyyy-MM-dd HH:mm:ss`; 전국 명세 `YYYYMMDDHHMMSS` |
| 갱신 구분/시점 | `UPDATEGBN`, `UPDATEDT` | `DAT_UPDT_SE`, `DAT_UPDT_PNT` | 수정시점과 구분해 보관; 전국 갱신시점 명세는 `YYYYMMDDHHMMSS` |

이번 서울 응답의 40개 필드에는 인허가취소일·휴업 시작/종료일·재개업일이 없었다.
다른 과거 데이터 설명에 등장하는 필드를 현재 실응답에도 있다고 가정하지 않는다.

| 인허가일 누락 / 비어 있지 않은 값의 날짜 파싱 실패 | 0 / 0 |
| 폐업일 누락 | 159건 (15.9%) |

| 좌표 X/Y 누락 | 각각 38건 (3.8%), 같은 행에서 누락 |

폐업일 누락 159건은 모두 이번 표본에서 영업 상태였다. 날짜가 비어 있다는 사실만으로 오류라고 집계하지 않는다.
위 비율은 전국 또는 구로구 전체의 누락률이 아니다.
전국 식별자 유일성, 전체 모집단 누락률, 좌표 범위 오류, 주소와 좌표의 일치 여부는 아직 확인하지 않았다.

### 실제 관측 상태 조합

| 일반 코드 | 일반 상태 | 상세 코드 | 상세 상태 | 건수 |
| --- | --- | --- | --- | --- |
| `01` | 영업/정상 | `01` | 영업 | 159 |
| `03` | 폐업 | `02` | 폐업 | 841 |

이 두 조합만 관측했다. 휴업·취소 등 다른 코드의 의미를 추측해서 추가하지 않는다.
코드는 앞의 `0`을 보존하는 문자열로 취급한다.

## 좌표

서울시·구로구 공식 설명과 전국 API 설명은 **EPSG:5174**를 명시한다.
좌표는 투영 좌표이며 경도·위도가 아니다. 실제 서울 응답 예시는 `X=187383.887301783`, `Y=444494.697447518`이다.

지도 구현 시 5174에서 4326으로 변환하고 X/Y 축 순서를 명시해야 한다.
좌표가 비어 있는 행은 마커에서 제외하고 별도 누락 통계에 포함한다.
이번에는 좌표 변환이나 지도상 위치 대조까지 검증하지 않았다. 주소만으로 좌표를 임의 생성하지 않았다.

## 전국 API 인증과 갱신 - 명세 확인, 실호출 미검증

기본 주소: `https://apis.data.go.kr/1741000/general_restaurants`

| 항목 | 게시된 명세에서 확인한 내용 |
| --- | --- |
| 현재 자료 | `GET /info` |
| 인증 | 필수 `serviceKey`; 개발·운영 계정 자동승인 안내 |
| 페이지 | 필수 `pageNo`, `numOfRows`; 페이지당 최대 100건 |
| 형식 | 선택 `returnType`; JSON/XML 제공 |
| 지역 조건 | `cond[OPN_ATMY_GRP_CD::EQ]` |
| 인허가일 조건 | `cond[LCPMT_YMD::GTE]`, `cond[LCPMT_YMD::LT]` |
| 상태 조건 | `cond[SALS_STTS_CD::EQ]` |
| 갱신 구간 | `cond[DAT_UPDT_PNT::GTE]`, `cond[DAT_UPDT_PNT::LT]` |
| 검색 조건 | 사업장명 LIKE, 도로명주소 LIKE |
| 호출량 안내 | 개발계정 10,000; 운영계정 활용사례 등록 시 증설 신청 안내 |
| 갱신 | 전국 `/info` 설명은 매일 갱신, 2일 전 기준 현행화 |
| 서울 자료 | 서울 공식 설명은 매일 갱신, 3일 전 자료 제공 |

응답 항목 위치는 `response.body.items.item`, 전체 건수는 `response.body.totalCount`로 명세되어 있다.
실제 응답의 빈 문자열/null 처리, 페이지 시작값, 변경 구간 경계 동작, 정렬 안정성, 삭제 자료 처리 방식은 인증 호출로 추가 검증해야 한다.
두 제공 경로의 갱신 지연 안내가 다르므로 동일 시점 스냅샷으로 취급하지 않는다.

### 과거 이력 API가 존재함

공식 Swagger에는 `GET /history`가 있다.
설명상 과거에 공개되었던 상태를 조회하며, 데이터기준일자는 **2026-01-01부터 조회일 전일**까지 입력 가능하다.
파라미터명은 `cond[BASE_DATE::EQ]`이지만 설명에는 '미만'이라는 표현도 있어, 정확한 날짜 경계는 실호출 전까지 확정하지 않는다.

이 기능을 완전한 사업장 상태 변경 이벤트 이력으로 간주하지 않는다.
2026년 이전 자료의 완전 복원도 보장하지 않는다.
기획서의 날짜 기반 추정 지도와 `/history`의 과거 공개 스냅샷은 서로 다른 기능이므로 이후 응답 대조가 필요하다.

## 이용 조건

- 전국 API: 공식 카탈로그에 무료, 이용허락범위 제한 없음으로 표시됨.
- 구로구 서울 페이지: 이용허락범위 제한 없음으로 표시됨.
- 동일 지역 자료를 연결하는 공공데이터포털 항목은 공공저작물 출처표시 제1유형으로 표시됨.
- 서울 전체 자료는 공공누리 제1유형으로 표시됨.

표시가 완전히 일치하지 않으므로 출처를 생략해도 된다고 결론 내리지 않는다.
샘플 및 서비스에는 제공기관, 데이터셋 링크, 취득일, 가공 여부를 표시하는 방식을 채택한다.
최소 서비스 필드만 보관하고 원본의 전화번호·인원·금액 등을 무차별로 재배포하지 않는다.

## 다음 구현 전 결정

1. 학습용 샘플 입력은 저장한 구로구 서울 형식으로 진행할 수 있다. 전국 API와 같은 파서로 처리하지 않는다.
2. 실제 적재 키는 원천 데이터셋 구분과 관리번호의 조합을 후보로 삼되 전체 범위 중복 검증 후 확정한다.
3. 일반음식점 업종과 `한식` 등의 업태를 별도 개념으로 둔다.
4. 날짜 기반 상태는 `인허가일 <= 기준일 AND (폐업일 없음 OR 폐업일 > 기준일)`인 추정으로 표시한다.
5. 날짜·좌표 원문과 정규화 실패 이유를 구분할 수 있도록 설계한다. 좌표 누락을 `(0,0)`으로 바꾸지 않는다.

## 남은 검증

- 전국 API 인증키 확보 후 `/info`와 `/history` 실제 응답 대조.
- 전체 파일 다운로드 가능 여부, 인증 및 호출 제한의 실제 적용 확인.
- 좌표 변환 후 주소와 지도상 위치 검증.
- 변경분 재수집 시 페이지 안정성, 중복·삭제 및 갱신 구분 값의 의미 확인.
- 미용업·노래연습장 등 나머지 업종 실응답 조사. 완료 전에는 Task 0 전체 완료로 처리하지 않음.
