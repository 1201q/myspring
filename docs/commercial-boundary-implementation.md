# 전국 주요상권 경계 확보·지도 연결

확보·검증일: 2026-11-22 (한국시간). 브랜치: `feature-commercial-area`.

## 확보한 범위

[소상공인시장진흥공단 주요상권현황](https://www.data.go.kr/data/15090955/fileData.do)의 `20240101` CSV를 공공데이터포털의 다운로드 버튼으로 확보했다. 페이지의 행 수 안내는 1,168이었지만 실제 CSV를 파싱한 결과는 **1,227개**다. 실제 파일을 기준으로 발행한다.

- 원본 크기: 30,458,403바이트. EUC-KR/CP949 호환 인코딩.
- SHA-256: `23415574515072d7348b933495f498205015f222e9ce6b8ea5e7e02fb3b6358d`.
- 실제 자료 기준일: 전 행 `2024-01-01`. 포털 수정일 `2025-08-12`와 다르다.
- 유형구분: 전 행 `주요상권`(원본 뒤쪽 공백 제거).
- 전국 17개 시도, 상권번호 중복 없음. 좌표 898,875개.
- 이용 조건: 확보 당시 공식 페이지의 ‘이용허락범위 제한 없음’ 확인.

[소상공인365 간단분석](https://bigdata.sbiz.or.kr/#/hotplace/gis)에서 ‘주요 상권’ 선택 시 발달상권 1,227개, 전통시장·상점가 2,138개로 표시되는 것을 확인했다. 화면에 노출된 `10065 서울소공동우체국`, `10058 경복궁역6번 출구` 등의 ID·명칭이 CSV와 일치한다. 사용자 제공 익산 화면에 나온 `익산영등2동우체국`도 CSV의 `10931`에 존재한다.

**발달상권의 개수와 표본 ID·명칭을 대조한 수준**이다. 소공365의 전체 내부 경계 좌표를 추출·대조한 것은 아니므로 모든 정점의 완전 일치를 주장하지 않는다. 우리 지도에는 공식 공개 CSV 좌표를 그대로 사용한다.

**전통시장·상점가 경계는 이번 원본에 없다.** 전국 전통시장 현황·위치 표준의 시장 위치점을 임의 반경으로 확장해 그 경계라고 표시하지 않는다. 동일한 전국 경계 발행본을 확보하기 전에는 해당 유형을 제공하지 않는다. 발달상권 목록에 시장명이 들어 있어도 별도 전통시장 유형으로 재분류하지 않는다.

## 변환과 보존

- 원본은 [압축 보관본](data-samples/commercial-boundaries/major-areas-20240101.csv.gz), 확인 수치는 [검증 메타데이터](data-samples/commercial-boundaries/verification.json)에 있다.
- [변환 스크립트](../scripts/build-commercial-boundaries.mjs)는 인용된 CSV 셀·줄바꿈을 보존하고 `경도,위도|경도,위도` 문자열을 GeoJSON으로 바꾼다.
- `)|(`로 분리된 링을 단순 연결하지 않는다. 포함 관계에 따라 내부 구멍과 독립 폴리곤을 구분한다. 여러 링을 가진 상권은 440개다.
- 원본의 숫자 정밀도와 모든 정점을 유지한다. 링 방향만 GeoJSON 방향으로 맞춘다. 반올림·단순화·임의 버퍼 없음.
- 좌표 개수·국내 위경도 범위·링 닫힘·0 면적·상권 ID·기준일을 검사한다. 위상 오류 전체를 독립 GIS 엔진으로 검증한 것은 아니다.
- [정적 지도 자료](../frontend/public/data/commercial/manifest.json)는 시도별 파일로 분리했다. 전체 약 32.6 MB이며 사용자가 레이어를 켠 지역만 요청한다. API 키·외부 상권 API 런타임 호출은 필요 없다.

재발행:

```powershell
# 보관된 원본으로 재생성
node scripts/build-commercial-boundaries.mjs

# 공식 다운로드 파일을 새로 보관하고 생성
node scripts/build-commercial-boundaries.mjs --input 'C:\path\official.csv'
```

새 버전의 건수·기준일이 바뀌면 자동으로 발행하지 않고 검사에 실패한다. 원천 변경을 검토한 후 기준을 갱신한다.

## 화면 동작

‘지도 레이어 → 상권 영역’으로 켠다. 기본은 꺼짐이다.

- 줌 9 이상에서 경계와 옅은 면을 표시한다. 선택 경계는 accent 색으로 강조한다.
- 재생 시도에 해당하는 상권을 검색·선택한다. 전남광주 재생 지역은 원천의 광주·전남 두 파일을 합친다. 원본 시도·시군구 코드는 그대로 보존하며 현재 행정동 ID와 결합하지 않는다.
- 목록 선택 시 상권 범위로 확대한다. 지도 영역 클릭도 정보 독을 열고 선택 정보를 표시한다.
- 검색 대상은 상권명·시군구명이다. 상세에는 상권번호·원천 지역명과 자료 기준일을 표시한다.
- 개폐업 재생 기간에 따라 경계가 변하지 않는다. 통계·매출·상권별 개폐업 집계는 이번 경계 표시 기능에 포함하지 않는다.
- 레이어를 끄면 지도와 독에서 숨긴다. 독만 닫으면 지도는 유지되며 영역을 다시 누르면 독이 열린다.

## 검증

`npm run build`, `npm run lint`, `node --test 'src/**/*.test.mjs'`로 검사한다.

추가한 테스트는 긴 CSV 처리, 구멍·독립 폴리곤 분리, 뒤집힌 좌표·누락 정점·열린 링 거부, 실제 1,227개 원본 대비 모든 정점·ID·명칭 보존, 전남광주 병합과 전북 52 코드, 요청 실패 처리를 검증한다.

실제 브라우저에서 서울 176개 로드, ‘서울소공동’ 검색, `10065` 선택 확대, 지도 클릭 후 정보 독 재열기를 확인했다. 375·820·1440px 화면과 라이트·다크 테마를 확인했고, 지하철 경계 동시 표시와 정보 독의 세 탭 전환도 확인했다. 모바일에서 상세 내용이 잘리는 문제를 발견해 본문 스크롤 방식으로 수정한 후 출처까지 스크롤해 접근할 수 있음을 확인했다. 백엔드는 실행하지 않아 개폐업 재생 API는 오류 상태였으며, 실제 개폐업 점과 경계의 동시 클릭·시도 전환 흐름은 이번 브라우저 검증에서 확인하지 못했다.

디자인 시스템 Artifact 링크는 로그인 화면으로 연결되어 읽지 못했다. 저장소 `frontend/CLAUDE.md`의 명시된 규칙과 기존 CSS 토큰·레이어 시트·정보 독을 사용했으며 원격 디자인 시스템 문서는 변경하지 않았다.

## 트렌드 상권 6종 연결 (2026-11-23)

공식 SHP 원본 6개를 내려받아 DBF의 `MJR_BZZNNO`를 기존 경계 ID에 연결했다. MZ 1,060개, 회식 904개, 배달 1,226개, 성장 1,227개, 신생 1,227개, 역주행 1,003개이며 미연결 ID는 없다. 이름은 일부 다르므로 이름으로 연결하지 않는다. 기존 WGS84 경계를 사용해 공개 파일의 수록 여부를 표시한다. SHP 좌표와 기존 경계의 정점 동등성까지 확인한 것은 아니다.

[검증 자료](data-samples/commercial-trends/verification.json)에 출처 URL, ZIP·SHP·DBF 해시와 상권번호 목록을 보관했다. 내려받은 ZIP은 로컬 `data/research-commercial/trends/`에 있다. [생성 스크립트](../scripts/build-commercial-trends.mjs)는 이 검증 자료의 ID 목록과 현재 경계 버전을 확인하고, 약 55KB의 `frontend/public/data/commercial/trends.json`을 발행한다. 원본 SHP를 6벌 브라우저로 보내지 않는다.

```powershell
node scripts/build-commercial-trends.mjs
```

기존 ‘상권 영역’ 독에서 전체와 6개 주제를 하나씩 선택한다. 선택한 주제는 지도 경계와 목록에 함께 적용되며 시도 변경·레이어 재열기 시에도 유지된다. 검색은 해당 주제의 상권명·시군구명에 적용한다. 주제를 바꿔 제외된 상권의 상세·강조는 해제한다. 상세에는 여러 공개 파일에 수록된 주제를 배지로 표시한다. 출처·기준일은 접을 수 있는 자료 정보에 넣었다. 로딩 실패는 다시 시도하거나 전체 경계로 돌아갈 수 있게 한다.

성장·신생 원본은 SHP와 DBF가 각각 바이트 단위로 동일하고 모두 기존 1,227개 전체를 담는다. 재가공본 2종도 같은 ID 전체에 양성 라벨을 부여한다. 사용자가 소상공인365 화면에서는 다르다고 확인했으므로, 이를 서비스 내부 분류와 동일하다고 주장하지 않는다. 요청에 따라 6종 모두 활성화하고 성장·신생 선택 시 공개 파일 수록 범위가 같다는 안내를 표시한다. 소공365와 정확히 같은 분류를 제공하려면 실제 선정 목록 또는 조건을 별도로 확보해야 한다.

원본의 `CRTR_YM`은 전부 `202401`이고 포털 안내는 2025년 8월이다. 두 날짜를 구분하며 주제 선정 시점은 미확정으로 명시한다. 파일에 매출·유동인구 수치는 없다. 수록 여부를 순위·강도·실시간 트렌드로 해석하지 않으며, 미수록을 특성 없음으로 표시하지 않는다. 원본 `BIZON_ARE_=1`은 모든 파일에서 동일하므로 6종을 구별하는 라벨로 쓰지 않는다.

6종 ID 연결·중복 주제·지역별 필터·미수록 처리·잘못된 형식·요청 실패 테스트를 추가했다. 실제 브라우저에서 6종 전환, 검색과 선택, 지역 변경 후 주제 유지, 두 테마와 375·820·1440px 화면을 확인했다. 빌드·린트·Node 테스트 28개가 통과했다.
