수집 설정: [commercial-area-v1](../config/collection-profiles.json).

15개 모두 공식 스키마에 인허가일·폐업일·상태·주소·원천 X/Y 좌표 필드가 있다. 필드 존재가 각 행의 유효한 날짜·좌표, 과거 자료 완전성, 정확한 좌표계를 보장하지 않는다. 업종별 좌표계 검증과 실제 파일 품질 검사는 계속 필요하다.

원본 확보·검사 완료는 일반음식점·미용업·노래연습장업·약국 4종, 2,905,642건이다. 나머지 11종의 공개 조회 합계는 1,173,971건이며 아직 전체 CSV를 확보하지 않았다. 이 범위에서 서버 공통 DB에 적재된 업종은 약국뿐이다. 목재수입유통업은 기존 데이터를 보관하되 이 수집 프로필에서 제외한다. 이 설정만으로 기존 화면이나 API의 집계 대상이 자동 변경되지는 않는다.

## 실행

```powershell
# 선택된 15종과 기존 파일 여부 확인: 네트워크·파일 생성 없음
python scripts/collect-national-permits.py --profile commercial-area-v1 --dry-run

# 원본 수집·품질 검사: 기존 완료 파일 재사용, DB 적재는 하지 않음
python scripts/collect-national-permits.py --profile commercial-area-v1 --download
```

프로필과 개별 `--slug`/`--category`를 섞으면 오류로 처리해 의도하지 않은 범위 확대를 막는다. 실행 기록에 프로필과 실제 선택 목록을 남긴다. `--group`은 프로필 안의 일부 그룹만 선택할 때 사용할 수 있다.

설정 단계에서는 대상 설정과 검증만 수행했다. 이후 원본 확보 결과는 아래와 같다.

## 2026-11-05 실제 수집 결과

15종 전부 완료했다. 기존 4종을 재사용하고 11종을 새로 받았다. 총 **4,079,799건**, 원본 **1,260,230,591바이트(약 1.26 GB)**이며 전체 수집·검사 실행은 약 95초 걸렸다. 이 시간에는 DB 적재가 포함되지 않는다.

앞의 공개 조회 표와 186건 차이가 나는 것은 새로 받은 파일과 기존 11월 4일 원본의 기준이 다르기 때문이다. 모든 파일을 동일 날짜 스냅샷으로 간주하지 않는다. 신규 확보분은 1,174,157건이다.

- 기관코드+관리번호 중복, 식별자 누락, 열 개수 오류: 각각 0건.
- 좌표 누락: 297,321건(약 7.29%). 숫자로 존재하는 좌표의 실제 위치 정확도는 아직 검증하지 않았다.
- 현재 폐업 상태지만 유효한 폐업일 없음: 9,091건.
- 미래 폐업일: 9건. 잘못된 폐업일 형식/날짜: 4건. 잘못된 인허가일: 10건.
- 매우 오래된 날짜 등 다른 검토 사유도 포함해 15종 모두 품질 검토 대상으로 표시됐다. 수집 완료가 품질 문제 없음이라는 뜻은 아니다.

업종별 실제 건수·다운로드 날짜·파일 해시·검사 집계는 [수집 검증 결과](data-samples/national/commercial-area-collection-verification.json)에 보관했다. 상세 검사 보고서와 원본은 Git에서 제외된 `data/national-collection/reports/20261105T085908Z-7c291b05` 및 `data/national-audit`에 있다.

서버 DB 변경·Docker 조작은 수행하지 않았다. 다음 단계는 품질 사유를 유지하며 공통 DB에 순차 적재하는 것이다. 지도 연결 전에 전국 좌표계 검증이 별도로 필요하다.
