# 전국 시도별 GPU 시간 재생

2026년 11월 현행 행정구역 기준의 전국 16개 시도를 지원하되, 브라우저는 선택한 시도의 이벤트 파일만 받는다. 현재 화면은 별도 모드 전환 없이 이 지역별 시간 지도로 바로 진입한다. 전국 전체를 한 파일로 내려받아 동시에 그리는 모드와 구분한다. 한 시도 안에서 월·기간·업종·확대 단계를 바꿀 때에는 같은 숫자 배열에 GPU 필터를 적용한다.

## 발행과 조회

```text
현재 인허가/지도 좌표 스냅샷
        ↓ 전국 커서 조회 한 번, 현재 주소로 시도 분류
data/playback/national/{regionId}/
        ├ manifest.json: 날짜 범위·업종·월별 전체 집계
        └ events-{version}.bin: 버전 고정 좌표/월/종류/업종/ID
        ↓ 선택 시도 파일만 다운로드
브라우저 GPU 월/업종 필터 + 선택 시도 전체 통계
```

시도는 서울·부산·대구·인천·대전·울산·세종·경기·강원·충북·충남·전북·전남광주·경북·경남·제주이며 ID는 각각 `seoul`, `busan`, `daegu`, `incheon`, `daejeon`, `ulsan`, `sejong`, `gyeonggi`, `gangwon`, `chungbuk`, `chungnam`, `jeonbuk`, `jeonnamgwangju`, `gyeongbuk`, `gyeongnam`, `jeju`이다.

전라남도와 광주광역시는 2026-07-01 전남광주통합특별시로 통합 출범했다. [행정안전부의 2026-06-15 안내](https://mois.go.kr/frt/bbs/type010/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000008&nttId=126845)에 근거해 현재 주소의 `전남광주통합특별시`와 종전 광주·전남 별칭을 모두 `jeonnamgwangju`로 분류한다. 이미 현행 명칭으로 바뀐 주소를 근거 없이 과거 광주/전남으로 나누지 않는다. 1990년대 이벤트도 현행 지역 기준으로 재생하는 것이며, 당시 행정구역별 집계를 복원하는 기능이 아니다. `전남광주`의 bbox는 `[124.8,33.7,127.95,35.6]`이다.

분류는 현재 도로명주소를 우선하고, 비어 있으면 지번주소를 사용한다. 앞뒤 공백을 제거한 주소의 첫 공백 구분 토큰을 시도 별칭과 정확히 매칭한다. 정식 명칭 외에 서울시/서울, 경기도/경기, 충청북도/충북 등의 축약, 강원도/강원특별자치도, 전라북도/전북특별자치도, 제주도/제주특별자치도 같은 구·신 명칭, 부산·대구·인천·광주·대전의 옛 직할시 명칭도 지원한다. 알려진 시도로 분류할 수 없는 주소나 유효한 지역 좌표 범위를 벗어난 기록은 제외한다. 좌표 범위는 잘못된 위치를 거르는 안전 검사이며 행정경계 폴리곤 판정이나 과거 주소 복원을 대신하지 않는다. 따라서 결과는 원본 전국 모든 사업장의 완전한 역사 기록이 아니라, 지원 업종과 변환 가능한 좌표 및 발행 조건을 충족한 신고 이벤트다.

시도별 다운로드와 통계를 분리하므로 서울 밖을 선택할 때 이전 시도의 점과 숫자가 남지 않아야 한다. 표시되는 순위·총계의 범위는 현재 선택한 시도 전체이며 현재 화면의 점 수나 전국 합계가 아니다.

## API 계약

| 요청 | 응답 |
|---|---|
| `GET /api/v1/map/playback/national/regions` | `{regions:[{id,name,bbox}]}`; DB 없이 지역 목록 제공 |
| `GET /api/v1/map/playback/national/{id}/manifest.json` | 해당 시도의 이벤트 버전·집계·지역 메타데이터 |
| `GET /api/v1/map/playback/national/{id}/events.bin?v={version}` | 해당 시도의 버전 고정 바이너리; immutable 캐시 및 ETag |

manifest에는 기존 서울 재생과 동일한 규격 필드 외에 `regionId`, 한글 `region`, `[west,south,east,north]` 순서의 `bbox`가 있다. `monthlyCounts`는 다음과 같이 인덱싱한다.

```text
((month - minMonth) × 2 + kind) × categoryCount + categoryCode
```

바이너리는 헤더 없이 16바이트 little-endian 레코드를 반복한다. 경도 float32(0), 위도 float32(4), 1990-01 기준 월 int16(8), 종류 uint8(10; 0=인허가/1=폐업), 업종 code uint8(11), 사업장 ID uint32(12)이다. `count × 16`이 파일 크기이며 SHA-256 앞 16자리가 버전이다. 인허가와 폐업은 각각 한 건이므로 이벤트 수와 고유 사업장 수가 다르다.

파일이 없는 첫 manifest 요청에는 `503` 및 `Retry-After`를 반환하며 공유 생성 작업을 시작한다. 여러 지역에 동시에 진입해도 지역마다 전체 DB를 다시 읽는 구조를 피한다. 준비가 끝난 뒤에는 파일을 제공하고 월 전환마다 SQL을 실행하지 않는다. 초기 발행 시간은 현재 DB 크기·디스크·네트워크에 따라 달라진다.

중복 발행은 두 단계로 막는다. 동일 JVM의 동시 요청은 `AtomicBoolean`으로 묶고, HTTP 서버와 CLI처럼 서로 다른 프로세스 사이는 `data/playback/national/.export.lock`에 대한 OS `FileChannel` 잠금으로 보호한다. CLI 발행 중 웹에 진입해도 두 번째 전국 DB 스캔을 시작하지 않는다. 아직 발행된 파일이 없으면 웹은 `503`으로 대기하며 잠금 사용 중 재시도 간격은 2초다. 다른 발행이 잠금을 가진 상태에서 CLI를 실행하면 이미 발행 중임을 명시하고 실패한다. 기존 파일이 있으면 웹은 그 파일을 계속 제공할 수 있다.

`.export.lock` 파일의 존재 자체는 발행 중이라는 뜻이 아니다. 실제 OS 잠금은 발행 완료나 프로세스 종료 시 해제되며, 남은 잠금 파일을 수동 삭제할 필요가 없다. 실행 중 파일을 삭제하면 서로 다른 파일을 잠그게 될 수 있으므로 그대로 둔다. 여러 서버가 각각 독립 로컬 디렉터리를 쓰는 배포에서는 이 잠금이 서버 간 전역 잠금을 대신하지 않는다.

## 수집 후 갱신

수집 및 지도 위치 스냅샷 갱신을 마친 뒤 명시적으로 전국 재생 파일을 다시 발행한다.

```powershell
.\scripts\export-national-playback.ps1
```

발행은 원본 DB를 수정하는 작업이 아니다. `.env.postgres`의 연결 설정을 사용하며 비밀번호를 로그에 출력하면 안 된다. 새 버전의 파일과 manifest를 발행한 뒤 서버는 새 manifest를 제공한다. 기존 브라우저는 이미 받은 배열을 계속 사용할 수 있으므로 최신 발행을 보려면 페이지를 새로고침한다. 구버전 파일은 이미 열린 클라이언트의 버전 URL을 위해 보존한다. 파일 존재만으로 원본 변경을 자동 감지하거나 실시간 반영하는 것은 아니다.

## 표시의 의미

- 1개월은 선택 월의 인허가/폐업 신고 이벤트다.
- 3개월·12개월은 선택 월을 포함한 과거 기간이다.
- 누적은 1990-01부터 선택 월까지의 신고 이벤트이며 해당 월에 영업 중인 사업장 수가 아니다.
- 위치와 시도는 현재 좌표/주소 스냅샷 기준이다. 주소 이전이나 행정구역 개편 이전의 위치를 복원하지 않는다.
- 마지막 월은 수집 시점과 신고 지연 때문에 미완성일 수 있다.
- 지도 라이브러리의 배경 타일 요청과 사업장 상세 API는 재생 이벤트 다운로드와 별도로 동작한다.

## 독립 검증

서버와 Vite가 실행된 상태에서 현행 16개 지역의 파일을 순서대로 받아 디코딩한다.

```powershell
$env:MAP_PLAYBACK_REQUIRE_NONEMPTY='1'
$env:MAP_PLAYBACK_MIN_REGION_EVENTS='1000'
node scripts/verify-national-playback.mjs
```

`MAP_PLAYBACK_REQUIRE_NONEMPTY=1`은 실제 전국 데이터에 16개 시도 모두 이벤트가 있는지도 강제한다. `MAP_PLAYBACK_MIN_REGION_EVENTS=1000`은 각 시도가 최소 1,000건을 포함해야 통과하게 해, 주소 별칭 누락으로 극소수 기록만 남는 문제를 잡는다. 기본값은 0이고 수집 범위에 맞게 조정할 수 있다. 이 임계값은 데이터 품질 검사 기준이며 실제 전체 기록의 완전성을 증명하지는 않는다. 기본 모드에서는 빈 파일도 유효한 형식으로 허용하되 결과의 `emptyRegions`와 `nonemptyRegions`에 표시한다. 지역 목록은 항상 정확히 현행 16개여야 한다.

다른 서버를 검증할 때는 `MAP_API_URL` 환경 변수 또는 `--base`를 사용한다.

```powershell
node scripts/verify-national-playback.mjs --base http://127.0.0.1:8080/api/v1/map
```

생성 중 manifest는 최대 10분 기다린다. `MAP_PLAYBACK_WAIT_MS=0`은 자동 대기를 끄며 최대 1800000ms까지 지정할 수 있다. 완료 보고서는 stdout의 JSON이고 생성 대기/지역별 진행은 stderr다. 결과를 보존할 때는 stdout만 JSON 파일로 저장한다.

검증 항목은 현행 16개 지역 ID의 유일성, manifest와 지역 목록의 일치, 모든 레코드의 좌표·월·종류·업종·ID 범위, 파일 길이, 전체 SHA-256/버전, 모든 월×종류×업종 집계의 정확한 일치, 개폐업 총계, immutable 캐시와 조건부 304 응답이다. 잘못된 지역·경로·버전 요청의 400/404, 기존 서울 API 호환성도 확인한다. 전국 발행 요약의 `scannedEvents`를 `publishedEvents`와 주소·좌표·업종 제외 건수로 대사하고, 16개 시도의 합계가 발행 건수와 같은지 검사한다. 전체 파일을 동시에 보관하지 않고 시도별로 검증해 메모리 사용을 제한한다.

브라우저에서는 서울→부산→제주 등 지역 전환 시 점·지역명·통계·지도 범위가 함께 바뀌는지, 느린 이전 요청이 뒤늦게 완료되어 화면을 덮지 않는지, 업종/누적/월 재생, 라이트/다크 전환, 상세 클릭과 작은 화면 레이아웃을 별도로 확인한다. HTTP 검증 통과만으로 모바일 FPS나 동시 접속 부하를 보장하지 않는다.

## 2026-11-08 실제 발행 및 검증

최종 발행은 약 3분 50초였다. 현행 16개 지역의 이벤트는 합계 **6,071,738건**(인허가 3,586,407 / 폐업 2,485,331), 파일 합계 97,147,808바이트다. 브라우저는 이 합계 전체가 아니라 선택한 지역의 파일만 받는다. 서울 1,443,310건, 부산 369,240건, 경기 1,321,087건, 전남광주 396,097건, 제주 102,842건을 포함한다.

검사한 6,071,769개 이벤트 중 주소 분류 불가 15건과 지역 좌표 범위 밖 16건을 제외했다. 미지원 업종 제외는 0건이다. 16개 지역 모두 최소 1,000건 기준을 통과했으며, 모든 바이너리의 월×종류×업종 집계·SHA-256·ETag/304·버전·지역 범위와 발행 요약 대사가 일치했다. 기존 서울 API도 HTTP 200을 유지했다. [전체 검증 결과](data-samples/national/national-playback-verification.json).

실제 브라우저에서 부산 누적 자동 재생, 경기 12개월 표시, 제주 업종 필터와 누적, 전남광주 전체 표시, 빠른 경기→제주 전환, 기록 지도 복귀 및 재진입, 라이트/다크 전환을 확인했다. 가로 1280px과 588px 화면에서 컨트롤을 확인했고, 588px에서 문서 가로 넘침은 없었다. [작은 화면의 제주 재생](data-samples/national/national-playback-browser.jpg). 해당 브라우저 검증 중 오류 로그는 없었다. 상세 점 클릭과 모바일 기기의 FPS·동시 접속 부하는 측정하지 않았다.

최종 Java 전체 테스트, 프런트엔드 빌드·lint, 지역 파일 로더 테스트 3개가 통과했다. 재생 코드는 첫 화면에서 별도 청크로 로드한다. MapLibre 기본 번들 및 재생 번들의 크기 경고는 남아 있다.

## 단일 지도 화면으로 통합

기록 지도와 지역 재생의 모드 전환을 제거했다. 첫 진입부터 지역 파일을 준비하며, 기본값은 서울·직전 월·1개월·일시정지 상태다. 지역·기간·업종 선택, 자동 재생, 점 상세 조회, 테마 전환은 같은 화면에서 사용한다. 기존 화면 범위 목록/PBF 사업장 레이어/존재 여부 날짜 조회는 프런트에서 제거했으며 관련 백엔드 API는 유지한다.

통합 후 브라우저에서 모드 버튼과 존재 여부 날짜 입력이 없는지, 첫 진입 시 자동 로드, 서울↔제주 변경, 약국 필터·12개월·누적·자동 재생을 확인했다. 제주 약국 점 클릭으로 상세 조회를 확인했고 확대·테마 전환 후에도 선택이 유지됐다. 월 변경 시 상세 선택이 해제됐으며 오류 로그는 없었다. 프런트 빌드·lint와 로더 테스트 3개도 통과했다. [통합 지도 화면](data-samples/national/unified-map-browser.jpg).
