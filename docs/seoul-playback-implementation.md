# 서울 전체 GPU 시간 재생

현재 지도 범위의 이벤트 JSON을 매번 받던 재생 경로를 서울 전체의 버전 고정 바이너리와 GPU 필터로 전환한다. MapLibre 배경/테마와 사업장 상세 API는 유지한다. 이 문서의 계약은 새 `SeoulPlayback` 경로에 해당하며 기존 `/events` API와 구분한다.

## 데이터 경로

```text
지도 조회 스냅샷(PostGIS)
       ↓ 서울 범위/행정 주소/이벤트 날짜 조건으로 한 번 생성
events.bin + manifest.json (data/playback/seoul)
       ↓ 버전 고정 HTTP 응답
브라우저 숫자 배열 → deck.gl GPU 월/업종 필터
       └ 월별 집계 배열 → 서울 전체 개폐업 총계·업종 순위
점 선택 → 기존 /api/v1/map/businesses/{id}
```

월, 재생 속도, 기간 단위를 바꾸거나 서울 안에서 지도를 이동할 때 이벤트 데이터 전체를 다시 DB에서 조회하지 않는다. 기본 지도/PBF 경로 및 다른 기능의 DB 부하 문제까지 모두 해결하는 변경은 아니다.

## API 및 최초 생성

- `GET /api/v1/map/playback/seoul/manifest.json`
- `GET /api/v1/map/playback/seoul/events.bin?v={version}`

첫 요청 때 파일이 없으면 생성 작업을 시작하고 `503`과 `Retry-After`를 반환한다. 동시 진입에 대해 중복 생성하지 않는다. 생성이 끝난 후 manifest와 버전 고정 바이너리를 받는다. manifest는 재검증하고 바이너리는 immutable 캐시를 활용한다. 월별로 SQL을 실행하지 않는다.

데이터는 기존 지도 스냅샷에서 생성하므로 원본 수집/좌표 갱신과 별도의 발행 주기를 가진다. 기존 파일이 있다고 원본 변경을 자동으로 탐지하거나 실시간 반영한다고 해석하면 안 된다.

수집 및 지도 위치 스냅샷 갱신 후 명시적으로 다시 발행한다.

```powershell
.\scripts\export-seoul-playback.ps1
```

이 스크립트는 기존 `.env.postgres` 설정을 사용해 `exportSeoulPlayback` 작업을 실행한다. DB 접속 비밀번호를 출력하지 않는다. 새 manifest는 원자적으로 발행되고 실행 중인 서버가 다음 manifest 요청에서 다시 읽는다. 오래 열린 브라우저는 숫자 배열을 계속 재사용하므로 새 버전을 보려면 페이지를 새로고침한다. 과거 버전 파일은 기존 클라이언트의 immutable URL을 위해 보존한다.

## 바이너리 규격

고정 16바이트, little-endian, 헤더 없이 레코드를 반복한다.

| 오프셋 | 자료형 | 필드 |
|---:|---|---|
| 0 | float32 | 경도 |
| 4 | float32 | 위도 |
| 8 | int16 | 1990년 1월=0인 정수 월 |
| 10 | uint8 | 0=인허가, 1=폐업 |
| 11 | uint8 | manifest categories의 연속 code |
| 12 | uint32 | 사업장 ID |

`count × recordBytes`가 파일 크기와 일치해야 한다. 한 사업장의 인허가와 폐업은 각각 독립 레코드이므로 이벤트 건수와 고유 사업장 수는 다르다. ID를 uint32에 저장할 수 있는 범위를 넘어서는 경우 조용히 잘라 쓰면 안 된다. 향후 전국 확장에서 ID/월 범위가 커지면 형식 버전을 올려야 한다.

manifest는 버전·생성일·바이너리 URL·필드 규격·서울 범위·월 범위·업종 목록·개폐업 총계와 월별 집계 배열을 제공한다. `monthlyCounts`의 인덱스는 다음과 같다.

```text
((month - minMonth) × 2 + kind) × categoryCount + categoryCode
```

집계와 점 데이터는 같은 발행 데이터로부터 만들어져야 한다. 서울 전체 총계는 화면에 실제로 보이는 점이나 현재 확대 단계의 개수로 계산하지 않는다.

## 표시 의미

- 1개월은 선택한 달에 발생한 인허가/폐업 신고만 표시한다.
- 3개월/12개월은 종료 월을 포함한 과거 3개월/12개월이다.
- 누적은 1990년 1월부터 선택 월까지 발생한 이벤트이며, 당시 영업 중인 사업장 수가 아니다.
- 실제 개점/영업 종료 및 당시 주소를 복원하는 데이터가 아니다. 위치는 현재 좌표 스냅샷 기준이다.
- 서울 범위는 데이터 발행 조건에 따른다. 전국 데이터와 합쳐 모든 지역의 전체 통계라고 표시하지 않는다.
- 데이터의 마지막 월은 신고 지연이나 수집 시점 때문에 미완성일 수 있다.

## 검증

서버와 Vite를 실행한 뒤 다음 명령으로 전체 바이너리를 독립 디코딩한다.

```powershell
node scripts/verify-seoul-playback.mjs
```

다른 서버를 검증할 때:

```powershell
$env:MAP_API_URL='http://127.0.0.1:8080/api/v1/map'
node scripts/verify-seoul-playback.mjs
```

검증기는 다음을 검사한다.

1. manifest 및 버전 고정 URL/HTTP 캐시 계약
2. 기존 10만 이벤트 제한을 넘는 전체 서울 데이터 제공
3. 레코드 길이·좌표·월·종류·업종·ID의 유효 범위
4. 모든 월×종류×업종 집계와 실제 바이너리 레코드 수의 정확한 일치
5. 전체/단일 월/이전 기간 합산의 경계 일치
6. ETag가 제공되면 조건부 요청의 304 재사용

생성 중 503이면 `Retry-After`에 따라 manifest 준비 상태를 최대 10분 확인한다. 서버의 단일 생성 작업을 재사용하며 월별 DB 조회를 반복하는 방식이 아니다. 자동 대기를 끄려면 `MAP_PLAYBACK_WAIT_MS=0`으로 지정한다. 0~600000ms 범위만 허용한다.

HTTP 데이터 검증과 브라우저 렌더링 검증은 별개다. GPU 필터 재생, 서울 전체 줌, 장시간 누적, 업종 변경, 다크/라이트 모드, 상세 클릭 및 작은 화면 레이아웃은 실제 브라우저에서 확인해야 한다. 개발 기기의 단일 실행 결과를 모든 기기의 FPS나 동시 접속 성능 보장으로 해석하지 않는다.

## 2026-11-08 실제 데이터 검증 결과

개발 DB에서 최종 서울 주소 조건으로 발행한 뒤 Vite 프록시를 통해 전체 파일을 받았다. 이벤트 1,443,310건(인허가 807,747 / 폐업 635,563), 23,092,960바이트, 15개 업종, 443개월이었다. 모든 바이너리 레코드에서 독립적으로 계산한 월×종류×업종 집계가 manifest와 정확히 일치했다. SHA-256과 버전, 좌표 범위, HTTP immutable/ETag 및 조건부 304도 통과했다.

최종 CLI 파일 생성은 약 1분 56초, 준비 완료 후 재검증은 전체 파일 수신·디코딩·검증까지 약 443ms였다. 캐시/디스크 상태를 통제한 성능 시험이 아니며 모바일 FPS나 동시 접속 부하 측정값은 아니다. [실행 기록](data-samples/national/seoul-playback-verification.json).

로컬 브라우저에서 서울 전체 줌 10.2의 누적 자동 재생(1994-12 → 1996-11), 2026-10 단일 월, 전체 업종 → 약국 필터, 줌 9.2 축소, 라이트/다크 전환을 확인했다. 해당 확인 중 브라우저 오류 로그는 없었다. [누적 재생 화면](data-samples/national/seoul-playback-browser.jpg). 상세 점 클릭, 작은 화면 및 모바일 FPS는 이번 브라우저 검증에 포함하지 않았다.

최종 Java 전체 테스트와 프런트엔드 TypeScript/프로덕션 빌드 및 lint가 통과했다. 번들 크기 경고는 남아 있다.
