# SeoulPulse 시간 재생 구조 분석

분석일: 2026-11-08. 공개 배포 JavaScript, JSON 메타데이터, 이벤트 바이너리를 읽어 확인했다. 서버 소스나 비공개 인프라에는 접근하지 않았다. 이 문서는 분석 결과이며 프로젝트 구현을 변경하지 않는다.

## 결론

SeoulPulse의 핵심 재생 경로는 `서울 전체 정적 바이너리 → TypedArray → deck.gl GPU 필터 → 점 표시`다. 기간별 총계/업종 순위는 점 렌더링과 분리된 월별 히스토그램에서 계산한다. 매 프레임 DB 조회나 화면 bbox에 따른 이벤트 다운로드를 하지 않는다.

우리 서비스의 현재 경로는 `현재 bbox의 이벤트 JSON → GeoJSON → MapLibre 필터`다. 재생 중 월마다 DB를 조회하지 않는 점은 같지만, 전체 지역을 작은 데이터로 보관하고 GPU에서 직접 기간을 필터링하는 구조까지는 구현하지 않았다. 줌 12/10만 이벤트 제한은 현재 구현의 운영 제한이며, PBF나 MapLibre의 절대 한계가 아니다.

해시가 있는 번들 URL은 배포 이후 달라질 수 있다. 분석 시 번들에서 확인한 함수 이름도 압축 빌드에 종속된다.

## 전체 이벤트 데이터

`qk()`는 최초 진입 시 events.bin과 meta.json을 병렬 fetch한다. 이벤트 파일을 DataView로 읽고 인허가/폐업을 각각 분리한 숫자 배열을 만든다.

| 항목 | 실제 확인값 |
|---|---:|
| 파일 크기 | 23,934,192 bytes (약 23.9 MB, 22.8 MiB) |
| 이벤트 개수 | 1,495,887 |
| 인허가 이벤트 | 819,770 |
| 폐업 이벤트 | 676,117 |
| 월 범위 | 1990-01 ~ 2026-11, 443개월 |
| 개별 사업장 기록 | stores_meta.json 기준 881,188건 |
| 생성 시각 | 메타데이터 표기 2026-11-04 23:36 |

파일 길이 / 16과 직접 디코딩한 개폐업 건수가 메타데이터와 일치했다. 이 개수는 이벤트 수이며 고유 사업장 수가 아니다. 인허가와 폐업이 모두 있으면 한 사업장이 두 이벤트를 갖는다.

### 이벤트당 16바이트

| 바이트 오프셋 | 필드 | 저장 형식 |
|---|---|---|
| 0~3 | 경도 | float32 |
| 4~7 | 위도 | float32 |
| 8~9 | 월 | signed int16, (연도−2000)×12 + 월−1 |
| 10 | 개폐업 종류 | uint8, 0=인허가, 1=폐업 |
| 11 | 업종 및 팝업 플래그 | uint8 |
| 12~15 | 사업장 상세 인덱스 | uint32 |

상호/주소 문자열을 모든 점에 반복해서 포함하지 않는다. 상세 인덱스로 별도 이름/사업장 데이터와 연결한다. 현재 JSON/GeoJSON의 객체·필드명·문자열 반복 비용과 다르다.

이벤트의 1990-01은 -120, 2026-11은 322다. 정수 월을 쓰므로 GPU에서도 날짜 문자열 파싱 없이 구간 비교가 가능하다.

## 렌더링

MapLibre는 OpenFreeMap 배경 지도를 표시한다. 그 위에 deck.gl MapboxOverlay를 추가한다(interleaved=false).

이벤트는 GeoJSON Feature 객체 대신 다음 TypedArray 속성으로 공급한다.

- 좌표: Float32Array
- 월: Float32Array
- 업종: Float32Array
- 상세 인덱스: Uint32Array
- 팝업 여부: Uint8Array

인허가는 ScatterplotLayer, 폐업은 X 모양 IconLayer를 사용한다. 두 레이어 모두 DataFilterExtension의 숫자 기간 필터와 업종 필터를 사용한다. 표시 기간은 `filterRange`로 전달되고, 좌표/날짜 버퍼를 월마다 다시 만들지 않는다.

1개월 재생은 같은 월 번호만 통과시킨다. 누적 재생은 1990-01을 시작값으로 고정하고 끝 월만 이동한다. 화면 확대/축소와 관계없이 전체 이벤트 배열이 이미 있으므로, 서울 전체 보기에서도 재생할 수 있다.

따라서 개발자 도구에서 보이는 PBF 요청과 개폐업 재생 데이터는 구분해야 한다. 이 배포의 개폐업 핵심 데이터는 events.bin이며 PBF가 아니다. 배경 지도는 별도 벡터 타일 경로를 사용한다.

이 구조도 GPU/메모리 사용량과 초기 다운로드 비용은 발생한다. 모든 기기에서 일정한 FPS가 보장된다는 뜻은 아니며, 이번 분석에서 FPS·모바일 최대 메모리는 측정하지 않았다.

## 기간별 총계와 순위

`qk()`는 이벤트를 디코딩할 때 동시에 `월 × 이벤트종류 × 업종슬롯`의 Uint32 히스토그램을 만든다. 일반 집계 bins와 팝업 보정 집계 popBins가 있다.

분석 번들의 슬롯 수 21, 월 수 443 기준으로 배열 하나는 `443 × 2 × 21 × 4 = 74,424 bytes`다. 두 배열을 합해도 약 149KB다. 점 149만 개를 매번 세지 않고 작은 월별 표를 더한다.

`oy()`는 선택 구간의 월과 업종을 순회해 다음을 반환한다.

- 전체 인허가/폐업 이벤트 수
- 업종별 인허가/폐업 이벤트 수
- 팝업 이벤트 보정값

현재 코드는 월별 히스토그램을 합산한다. 누적합(prefix sum)을 사용한다고 추정하지 않았다. 복잡도는 선택 개월 수 × 업종 수에 비례하며, 이벤트 수에 직접 비례하지 않는다.

순위 패널 `Z5()`는 선택 업종 중 noRank 항목을 제외한 후 인허가 수 내림차순으로 정렬한다. `이 기간에 개업 / 폐업` 문구는 이 순위 행들의 합으로 출력된다. 따라서 이 숫자는 원본 전체 업종/이벤트의 총계와 무조건 같지 않다. 업종 선택, 팝업 제외, 순위 제외 설정 및 기간을 함께 봐야 한다.

사용자가 언급한 101,779 / 47,659가 나온 정확한 월 범위·선택 업종은 주어지지 않아 같은 숫자 자체를 재현했다고 주장하지 않는다. 해당 문구에 값을 공급하는 계산 경로는 공개 코드에서 확인했다.

### 서울 전체와 현재 지도

- 서울 전체: 위 월별 히스토그램 합산을 사용한다. 지도에서 모든 점이 식별 가능하게 보이는지와 관계없이 통계는 계산된다.
- 현재 지도: `ay()`가 브라우저에 이미 있는 이벤트 배열에서 기간/좌표 bbox를 비교해 센다. 이 경로는 이벤트 수에 비례하는 CPU 연산이지만 DB 요청은 아니다.
- 동별: `seoul_dong.geojson`, `dong_month.bin`, `dong_index.json`을 별도로 받는다. 426개 동 × 443개월 × 6열의 Uint16 집계 자료가 정의되어 있다. 동별 순위도 매번 원시 좌표의 공간 조인을 하지 않고 미리 만든 집계를 더한다.

## 왜 현재 구현과 차이가 나는가

| 구분 | 현재 우리 구현 | 분석한 SeoulPulse |
|---|---|---|
| 재생 데이터 범위 | 현재 화면 bbox | 서울 전체 |
| 전송 | 이벤트 JSON | 16바이트 정적 바이너리 |
| 브라우저 데이터 | 객체 배열 + GeoJSON | 압축 해제 후 숫자 TypedArray |
| 표시 | MapLibre GeoJSON 필터 | deck.gl 숫자 버퍼 + GPU 필터 |
| 월별 총계 | 받은 이벤트 객체를 필터링 | 월·업종 히스토그램 합산 |
| 동별 통계 | 미구현 | 미리 만든 동별 월 집계 |
| 지도 이동 | 이벤트 DB 재조회 | 핵심 이벤트 재다운로드 없이 카메라/집계 갱신 |
| 상세 | ID로 Spring API | 별도 이름·상세 인덱스 파일을 필요 시 연결 |
| 범위 제한 | 줌 12 이상, 10만 이벤트 | 공개 코드의 기본 점 재생 경로는 전체 배열 사용 |

서울 전체를 보려면 제한 숫자만 늘리는 것이 아니라 데이터 공급 방식과 렌더링 경로를 바꿔야 한다. 같은 전체 데이터의 JSON/GeoJSON화는 객체 메모리, 파싱, worker 변환 비용이 크다.

## 우리 프로젝트에 적용할 방향 (설계 제안)

1. 원본 수집·정제·위치 갱신 뒤 재생용 데이터셋을 별도로 생성한다. 이벤트 ID, 좌표, 정수 월, 업종, 종류만 포함한다. 상호·주소·상세는 기존 API를 유지한다.
2. 서울/시도별 바이너리 파일과 메타데이터 manifest를 버전으로 발행하고 정적 파일/CDN으로 제공한다. 브라우저는 지역별 파일을 로드해 재사용한다.
3. MapLibre 배경·다크모드는 유지하고, 재생 점 레이어를 deck.gl binary attributes + DataFilterExtension으로 전환한다.
4. 월×시도×업종×종류 집계를 별도로 만든다. 전국/시도 합계와 순위는 확대 수준이나 점 로드 여부에 의존하지 않게 한다. 동별 분석이 필요하면 행정동×월 집계를 추가한다.
5. 서울 전역 누적·최대 기간·업종 변경·지도 이동·동시 접속과 메모리/FPS를 별도로 검증한 뒤 전국 보기로 확장한다.

전국은 서울보다 데이터가 커지므로 전체 파일 하나를 모든 기기에 강제로 내려주는 설계는 피한다. 지역/시기별 분할, 필요한 데이터만 로드, 광역 단계의 집계와 상세 점의 표현 수준 분리가 필요하다. 이는 적용 제안이며 SeoulPulse의 서버 구현을 확인했다는 의미가 아니다.
