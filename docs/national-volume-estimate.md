# 전국 업종 수집 규모 조사

2026-11-04 조사. 원본 전체 다운로드, DB 접속·변경, Docker 조작 없이 공식 공개 미리보기만 조회했다.

## 실측

- 인허가 195개 업종에 각각 첫 페이지 1회 요청: 195개 모두 `totalCount` 확인 성공.
- 공개 조회 건수 합계: **12,318,289건**. 영업 중·폐업 자료가 함께 포함된 인허가 행 수이며, 서로 다른 실제 점포 수가 아니다.
- 응답의 사업장 상세는 저장하지 않고 건수와 출처만 보관했다.
- 업종별 근거: [조회 결과 JSON](data-samples/national/category-volume-inventory.json).
- 재현: `python scripts/inventory-national-permits.py` (동시 요청 최대 2개, 각 요청 후 0.25초 대기, 자동 재시도 없음).

카탈로그의 CSV 경로는 결과에 함께 기록했으나, 이번 조사는 파일 서버에 전량 요청을 보내지 않았다. 실제 전체 CSV 확보가 확인된 것은 기존 5개 업종뿐이다. 195개 공개 조회 성공을 195개 파일 다운로드 성공으로 해석하면 안 된다. 원천 메뉴의 13개 보조 정보는 제외했다.

## 용량·시간 추산

다음은 측정된 완료 시간이 아니라 계획을 위한 가정이다. 업종별 행 폭, 서버 제한, 인덱스와 테이블 크기에 따라 달라진다.

| 항목 | 계산 및 의미 |
| --- | --- |
| 원본 CSV | 행당 270~400바이트 가정 시 약 **3.3~4.9 GB** (십진 단위). 실제 크기는 전체 파일 확보 후 확정 |
| 다운로드 | 실효 1 MB/s면 약 55~82분, 5 MB/s면 약 11~16분. 요청 대기·제한·검사·재시도 시간 제외 |
| 최초 DB 적재 | 기존 약국 70,770건/152초를 단순 비례하면 전체 약 **7.3시간**. 작은 업종의 실행 준비 비용, 큰 테이블에서의 성능 변화는 반영하지 않음 |
| DB 크기 | 기존 74,214건 적재 후 DB 전체 173,405,875바이트를 단순 비례하면 약 **28.8 GB**. 기존 테이블·인덱스 등 고정비 포함이라 정확한 예측은 아님 |

초기 운영 계획은 **수집·검사·적재에 하루 이상의 작업 창**을 두되, 전체 완료를 보장하는 시간으로 취급하지 않는다. 1~2개 큰 업종을 먼저 적재해 처리 속도·DB 증가량·서버 여유 공간을 다시 측정한 뒤 나머지를 진행한다. 현재 수집기의 파일당 1 GiB 제한에 걸리는 업종이 있는지도 실제 다운로드 전에 확인해야 한다.

DB 외에 원본, 임시 적재, WAL, 백업 공간도 필요하다. 서버의 현재 여유 공간은 이번 조사에서 확인하지 않았으므로 전체 적재를 곧바로 시작하지 않았다. 기존 Docker 서비스의 자원 사용을 고려해 순차 처리한다.

## 갱신 방향

최초 수집 후 날짜별 디렉터리로 원본을 받고 검사·적재를 예약 실행할 수 있다. 현재 수집기는 기존 CSV를 덮어쓰지 않으므로 같은 폴더에서 반복 실행하는 것만으로 최신화되지 않는다.

전체 원본을 매일 재처리하는 비용은 실측 후 결정한다. 변경분 API는 아직 실호출로 검증하지 않았으므로 증분 갱신이 이미 가능한 상태라고 표현하지 않는다. 예약 실행, 중복 실행 방지, 재시도·알림, 원본 보관 기간을 추가해야 한다.

전체 확보와 지도 분석 대상은 별도로 관리한다. 통신판매업처럼 주소가 오프라인 상권의 영업 장소를 대표하지 않을 수 있는 업종은 지도 집계에 일괄 포함하지 않는다. 폐업일이 없는 9종도 폐업 시점 재생에 제약이 있다.
