# 전국 인허가 지도 연결

## 현재 제공 범위

지도 화면: `http://127.0.0.1:5173/`, Spring API: `http://127.0.0.1:8080`.

전국 지역별 월별·누적 신고 재생은 별도의 [전국 GPU 시간 재생 경로](national-playback-implementation.md)를 사용한다. 기본 지도 타일·화면 목록 조회와 재생 파일 발행은 서로 다른 경로다.

수집 대상 **15개 업종의 유효 위치 3,782,478건**을 PostGIS 위치 테이블에 저장했다. 현재 정보 4,083,243건은 유지했다. 기존 `/api/v1/businesses` 샘플 API도 유지하며, 새 지도는 지도 전용 API를 사용한다.

15개 업종 각각의 공식 공공데이터포털 조회서비스 설명에서 EPSG:5174 선언을 확인했다. [근거 목록](data-samples/national/map-crs-evidence.json)에 URL·업종명·본문 지문·확인 시각을 보관한다. 나머지 12종의 서울·부산·제주 표본 36개도 예상 지역에 들어오는지 확인했다. 모든 개별 주소의 지오코딩 정확도를 보증하는 검증은 아니다.

15개 업종 중 좌표가 없는 297,321건은 지도에서 제외한다. 별도 목재수입유통업 3,444건은 지도 서비스 대상에 넣지 않는다. 지도상의 개수는 전체 인허가 건수가 아니다.

## 지도 API

```text
GET /api/v1/map/businesses?bbox=126.88,37.49,126.89,37.50&limit=500
GET /api/v1/map/businesses?bbox=126.88,37.49,126.89,37.50&category=general_restaurants&date=2020-01-01
GET /api/v1/map/categories
GET /api/v1/map/tiles/13/6983/3174.pbf?category=general_restaurants&date=2020-01-01
GET /api/v1/map/businesses/123
```

- `bbox`: 서쪽 경도, 남쪽 위도, 동쪽 경도, 북쪽 위도. 유한한 값이어야 하며 경도·위도 폭이 각각 1도 이하여야 한다.
- `category`: 생략하면 좌표가 있는 대상 업종 전체. `/api/v1/map/categories`가 선택 가능한 15종의 slug와 이름을 반환한다.
- `date`: 생략하면 폐업 기록을 포함한 원천 인허가를 표시한다. 지정하면 `인허가일 <= date`이고 `폐업일 없음 또는 폐업일 > date`인 행만 반환한다. 인허가일 미상인 행은 날짜 조회에서 제외한다.
- `limit`: 1~500, 기본 500. 최대 limit+1개를 읽어 `truncated`를 계산하며 전국 전체 COUNT를 하지 않는다. 공간 인덱스의 KNN 순서로 화면 중심 주변부터 읽는다. 결과는 화면 범위의 일부이며 최신순/ID순 정렬이나 페이지 순회 계약이 없다.
- 공간 조건은 GiST 인덱스로 먼저 좁히고 인허가 기본키로 지점 조회한다. 현재 정보의 해시·좌표·해석된 좌표계가 일치하는 완료된 수집 실행만 연결한다. 조회마다 좌표를 다시 변환하지 않는다.
- DB 조회 제한은 3초이며 초과하면 503과 확대 안내를 반환한다. 세계 전체 등 너무 넓은 요청은 400이다.

응답은 `items`, `limit`, `truncated`, `date`, `locationBasis`를 제공한다. 위치는 항상 `LATEST_KNOWN_SOURCE`다. 과거 날짜의 존재 여부는 행정 날짜로 추정하며 과거 주소·실제 영업 여부를 복원하지 않는다.

## 화면

### 월별 시간 재생 (2026-11-08)

하단 `시간 재생`을 선택하면 1990년 1월부터 한국 현재 월까지의 인허가/폐업 이벤트를 현재 화면 범위별로 한 번 조회한다. 시작 시 줌 14로 확대하며 줌 12 미만은 이벤트 조회를 중단한다. 이 모드에서는 일반 목록 요청과 사업장 PBF 표시를 멈춘다. 업종/화면 범위가 바뀔 때만 새 데이터를 받고, 월·속도·재생 단위 변경은 GeoJSON 레이어의 필터와 불투명도만 변경한다. 같은 범위의 최근 3개 결과를 최대 5분 재사용한다.

- 1개월: 선택 월의 신고 이벤트만 표시한다. 인허가일/폐업일이 해당 월 시작 이상, 다음 월 시작 미만인 조건이다.
- 3/12개월: 선택한 종료 월을 포함한 직전 3/12개월이다. 다음/이전 및 자동 재생은 해당 개월 수씩 이동한다.
- 누적: 1990년 1월부터 선택 월까지 발생한 이벤트를 표시한다. 당시 영업 중인 사업장 수를 의미하지 않는다.
- 청록색은 인허가, 주황색은 폐업 신고다. 한 사업장에 두 이벤트가 있으면 각각 집계한다. 같은 위치의 점은 겹칠 수 있다.
- 재생/일시정지, 0.5/1/2/4배속, 월 슬라이더, 월 입력, 이전/다음을 제공한다. 마지막 월에 정지하고, 끝에서 재생을 다시 누르면 1990년부터 시작한다. 지도 이동/업종 변경/점 선택 시 재생을 멈춘다.

API: `GET /api/v1/map/events?bbox=126.88,37.49,126.89,37.50&from=1990-01-01&to=2026-12-01[&category=pharmacies]`. `from` 이상, `to` 미만이며 최대 50년, bbox 각 폭 1도 이하다. 좌표 스냅샷을 사용하므로 기존 스냅샷 갱신 주기가 적용되고 과거 위치를 복원하지 않는다. 기록이 없는 달은 0건이며 데이터 수집 완료 여부를 보증하지 않는다.

최대 10만 이벤트를 넘으면 빈 items와 `truncated=true`를 반환하여 불완전한 표본 재생을 막고 확대를 안내한다. 이벤트 DB 조회는 동시에 최대 2개/SQL 8초 제한이며 초과 요청은 429다. 기존 타일 API 전체의 부하 제한을 해결하는 변경은 아니다.

검증: `node --test frontend/src/playback.test.mjs`, Gradle 이벤트/API 테스트, `node scripts/verify-map-playback.mjs`. 실제 구로 표본 전체 5,289 이벤트/194ms, 2020-10은 9 이벤트/75ms, 약국은 68 이벤트/33ms였다(단일 측정). 브라우저에서 월별 점·건수 전환과 4배속 자동 재생/정지, 3/12개월·누적 범위를 확인했다.

### 밝은 지도 테마 (2026-11-08)

배경은 OpenFreeMap의 Positron을 수정한 벡터 스타일 `frontend/public/styles/quiet-light.json`을 사용한다. 도로·건물·공원 색을 낮추고 작은 도로명과 도로 번호 라벨을 제거했다. 지명은 한국어/현지 이름을 우선한다. 출처 표시는 지도 하단에 유지한다. 데이터 PBF API와 목록 요청 방식은 변경하지 않았다.

점은 작은 청록색, 폐업은 낮은 불투명도의 회색으로 표시한다. 묶음은 10건 이상만 숫자를 표시하고 숫자 겹침을 방지한다. 1,000건 이상은 k 단위로 축약한다. 숫자를 생략한 묶음도 점과 클릭 기능은 유지한다. 선택 위치는 별도 원형 강조 레이어로 표시한다. 프론트 빌드·린트와 실제 브라우저의 배경/숫자/선택 위치 표시를 확인했다.

지도는 MapLibre의 vector source와 circle/symbol 레이어로 PBF(MVT)를 렌더링한다. HTML 마커를 전체 삭제·재생성하지 않으며 목록 조회 시작 때도 지도 데이터를 지우지 않는다. 지도 이동 시 MapLibre가 필요한 타일을 요청하고 재사용한다. 업종·날짜 변경은 타일 URL에 반영한다.

줌 6~14는 전역에 정렬한 32px 격자별 실제 건수와 평균 위치를 표시한다. 묶음을 누르면 확대한다. 줌 15~16은 개별 위치를 표시하며 이후 줌은 16 타일을 확대한다. 개별 점을 누르면 ID 기반 상세 API를 호출한다. 타일에는 목록의 500건 제한이 없다. 회색은 선택한 기준일(미선택 시 한국 현재 날짜)까지 폐업일이 기록된 인허가다. 지도 최소 줌은 6이다.

줌 10 이하에서는 인허가 점/건수 레이어를 비활성화해 해당 벡터 소스의 새 타일 로딩을 중단한다. 목록 요청과 대기 타이머도 취소하고 “확대하면 표시됩니다”를 표시한다. 배경 지도는 계속 제공한다. 줌 10을 넘으면 레이어를 다시 활성화하고 이동이 끝난 현재 범위로 목록을 조회한다. 이미 DB에서 실행 중인 쿼리가 클라이언트 취소와 동시에 중단된다는 보장은 없다.

목록은 기존 bbox API를 사용해 이동 후 200ms 대기하고 가까운 최대 500건을 조회한다. 이전 요청은 취소한다. 중단 기준은 화면 폭 대신 줌이며, 매우 넓은 화면에서는 API의 1도 제한에 맞춰 목록 조회 영역만 화면 중심 기준으로 좁힌다. 목록 건수는 지도 전체 건수가 아니다.

### 지도 전용 조회 스냅샷

타일은 `national_permit_map_tile_point` materialized view를 읽는다. 유효한 공개 위치 뷰에서 ID·업종·인허가일·폐업일·EPSG:3857 위치만 저장하여 큰 원본 행에 대한 반복 지점 조회를 피한다. 초기 설치는 대상 PostgreSQL에 `ops/postgres/map-tiles.sql`을 앱 역할로 적용한다. H2에는 적용하지 않는다.

수집 결과 공개, 위치 보정, CRS 근거 변경 후에는 다음 명령으로 갱신한다.

```powershell
.\scripts\refresh-map-tiles.ps1 -Database permit_map_dev
```

스냅샷은 자동 갱신되지 않는다. 갱신 중에는 이전 스냅샷을 제공한다. 상세·목록은 현재 유효 자료를 직접 조회하므로 갱신 전까지 타일과 차이가 날 수 있다. 타일 HTTP 캐시는 5분이며 갱신 직후 이미 열린 지도에는 새로고침이 필요할 수 있다. 타일 SQL은 개별 위치 10초/집계 30초 제한, 잘못된 줌/타일 좌표/업종은 400이다. 시간 자동 재생은 구현하지 않았다.

초기 설치는 지도 스냅샷을 geohash 순서로 `CLUSTER`하여 인접 위치가 같은 디스크 페이지에 모이게 한다. 수집 순서 그대로 두면 서울 외 지역의 첫 조회에서 흩어진 페이지를 읽느라 시간 초과가 발생할 수 있다. `CLUSTER`는 스냅샷 읽기를 잠시 막으므로 초기 설치/유지보수 때만 실행한다. 일반 갱신 스크립트는 읽기를 유지하는 concurrent refresh를 사용한다.

## PBF 전환 검증 (2026-11-06)

`node scripts/verify-map-tiles.mjs`는 실제 Vite 프록시를 통해 타일을 디코딩하고, 500건 초과 위치·과거 날짜/업종 필터·묶음·빈 타일·입력 검증·상세 API를 검사한다. 프론트 의존성 설치와 PostGIS 서버 실행이 필요하다. 다른 API 주소는 `MAP_API_URL`로 지정한다.

개발 DB의 스냅샷 3,782,478건으로 통과했다. 최종 1회 측정은 개별 타일 3,229점/99KB/347ms, 약국 날짜 필터 19점/43ms, 줌 12 집계 229개/292ms, 줌 6 집계 92개/3,996ms였다. 초기 광역 조회는 10.7초도 관측했으며 캐시·디스크 상태를 통제한 부하 테스트가 아니다. [실행 결과](data-samples/national/map-tiles-verification.log).

전체 Gradle 테스트와 프론트 빌드·린트가 통과했다. 실제 브라우저에서 묶음/건수 표시, 확대 후 개별 점 전환, 점 클릭 후 `학다방` 상세 표시를 확인했다. 마지막 브라우저 오류 로그는 비어 있었다. 배경 타일은 기존 OSM 이미지 타일을 유지한다.

서울 외 지역 후속 검증에서 부산 타일 30초/503, 제주 19초 지연을 발견했다. 서울 제한은 없었으며 수집 순서의 스냅샷이 지역별로 흩어진 디스크 페이지를 읽는 문제가 있었다. 지도 스냅샷 3,782,478행을 geohash 순서로 재배치하고 인덱스를 재구성했다. 이후 전체 PBF 통합 검증이 통과했고 부산 242개 묶음/311ms, 제주 186개/163ms, 대전 187개/284ms를 확인했다. 이 값도 각 1회 측정이며 실제 사용자 동시 부하나 통제된 cold-cache 벤치마크는 아니다. 검증 스크립트에 세 지역을 포함했다.

## 최초 좌표 채우기

먼저 PostGIS 설정 `ops/postgres/enable-spatial.sql`과 `ops/postgres/location-backfill.sql`을 관리자 권한으로 대상 DB에 적용한다. 이어서:

```powershell
.\gradlew.bat backfillNationalLocations -Pdatabase=permit_map_dev
```

원천 `source_crs=5174`와 유효한 X/Y가 있는 완료 자료만 변환한다. 입력의 넓은 TM 범위와 변환 후 한국 주변 사각 범위를 검사한다. 이 사각형 검사는 정확한 행정경계 검증이 아니다.

당시 원천 좌표계가 미확인이었던 12종은 공식 근거를 별도로 연결한다.

```powershell
.\scripts\verify-map-crs.ps1
.\scripts\apply-map-crs.ps1 -Database permit_map_dev
.\gradlew.bat backfillCatalogLocations -Pdatabase=permit_map_dev
```

첫 명령은 공식 상세 페이지 15개에서 업종명과 설명 메타데이터의 좌표계를 검증해 `src/main/resources/map-categories.json`과 증거 목록을 생성한다. 둘째 명령은 검증된 근거를 `permit_category_crs`에 넣는다. 셋째 명령은 기존 `source_crs IS NULL`인 대상만 처리한다. 원본 좌표계·원문 JSON·내용 해시·과거 관측 기록은 변경하지 않는다. 조회는 `COALESCE(원본 좌표계, 검증된 업종별 좌표계)`로 해석한다. 근거를 제거하면 미확인 자료의 위치도 조회에서 제외된다.

1만 ID 범위마다 변환과 체크포인트를 함께 커밋한다. SQL 20초/잠금 3초/실행 5분 제한이며 같은 명령으로 중단 지점에서 재개한다. 원본 현재 정보와 이력은 변경하지 않는다. 최초 실행의 최대 ID를 고정하므로 **일일 신규·수정 데이터 갱신용 작업이 아니다.** 향후 갱신에는 수집 실행별 위치 갱신 경로가 필요하다. 원천 내용이 바뀐 위치는 해시 불일치로 조회에서 제외한다.

## 2026-11-06 초기 3종 연결 검증

- 원본 ID 4,083,243개 범위를 처리하고 유효 위치 2,642,415건을 실제 테이블에서 확인했다. 잠금 해제와 원본 건수 유지 및 네 Docker 컨테이너 시작 시각·재시작 횟수 유지를 확인했다.
- 전체 H2 테스트 61개 통과, 별도 성능/공간 테스트 2개 제외. PostgreSQL 공간 통합 테스트 1개 통과: 재개 중복 방지, 이상 좌표 제외, 날짜 경계, 표시 한도, 원천 해시 변경 시 마커 제외를 포함한다.
- 프론트 TypeScript/배포 빌드와 린트 통과. MapLibre 번들 크기 경고는 남아 있다.
- 실제 Vite 프록시를 거친 구로·부산·울산·제주 20건 요청은 각각 193/92/113/43ms, 초기 화면 근사 범위 500건은 1485ms였다. 각 1회 확인값이며 부하 테스트 결과가 아니다. 업종·날짜 필터와 반환점의 화면 범위 일치를 확인했다. 세계 전체 요청은 400이었다.
- 브라우저 접근 호스트와 네이티브 파이프가 없어 화면 직접 조작·실제 WebGL 마커 렌더링은 검증하지 못했다. 프론트 HTTP 200, 프록시 요청/응답 및 서버 로그까지 확인했다.

## 2026-11-06 나머지 12종 추가 검증

- 대상 1,244,927건 중 좌표가 있는 1,140,063건 추가. 전체 실제 위치 3,782,478건과 원본 현재 정보 4,083,243건을 확인했다. 추가 변환은 13:23:16~13:27:21(KST), 약 4분 5초였다. 공식 근거 조사와 코드 수정·테스트 시간은 별도다.
- 15개 공식 카탈로그 선언을 직접 확인하고, 추가 12종의 지역 표본 36개를 확인했다. 좌표 누락 104,864건은 새 마커를 만들지 않았다.
- 실제 프록시 API에서 추가 12종 각각의 업종·범위 조건을 검증했다. 기존 일반음식점, 15종 목록 및 날짜 필터도 확인했다.
- 넓은 범위의 휴게음식점 날짜 조회가 기존 Bitmap 후보 읽기 계획에서 3초 제한에 걸렸다. 기존 GiST의 지도 중심 KNN 읽기와 LATERAL 기본키 조회로 수정했다. 같은 요청은 713ms, 초기 화면 근사 범위 500건은 170ms로 확인했다. 캐시 상태를 통제한 부하 비교는 아니다. [공식 KNN 설명](https://postgis.net/workshops/postgis-intro/knn.html).
