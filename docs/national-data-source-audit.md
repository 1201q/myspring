# 전국 복수 업종 원천 데이터 실검증

조사일: 2026-11-04 (KST)

후속으로 공식 전체 메뉴의 208개 서비스를 조사했다. 인허가 195종과 기타/보조 정보 13종의 목록 및 필드 검증은 [전체 업종 카탈로그](national-category-catalog.md)를 참고한다. 아래 전량 파일 검증은 3종에 한정된다.

## 결론

서울 전용 자료가 아닌 **전국 3개 업종 전체 CSV**를 공식 파일 서버에서 다운로드하고 모든 행을 검사했다.
총 2,834,872건이며 각 파일의 행 수가 같은 날 공식 무인증 샘플 조회의 `totalCount`와 일치했다.
실제 받은 전체 파일은 약 867 MB(원본 바이트 기준)이며 Git에서 제외되는 `data/national-audit/`에 보관한다.
DB에는 아직 적재하지 않았다. 원격 서버와 Docker에는 접근하지 않았다.

| 업종 | 전체 행 | 유효하게 파싱된 폐업일 보유 | 그중 2020년 이전 폐업 | 좌표 누락 | 누락률 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 일반음식점 | 2,309,440 | 1,634,627 | 1,183,238 | 161,278 | 6.98% |
| 미용업 | 461,011 | 263,989 | 180,005 | 27,523 | 5.97% |
| 노래연습장업 | 64,421 | 36,016 | 27,207 | 3,656 | 5.68% |

폐업일 보유는 날짜 파싱 성공을 뜻하며 실제 날짜의 정확성을 보증하지 않는다. 미래 날짜 등 별도 검토 대상도 포함한다.
좌표 누락 외의 숫자 좌표는 형식만 검사했다. 전국 범위의 좌표 변환 및 주소 대조까지 완료한 수치가 아니다.
지역 코드 없이 전량 요청했고 각 업종에서 230개 기관 코드가 관측됐다. 현재 공식 지역 선택지 그룹 모두에 행이 있지만, 이것만으로 전국 실제 인허가의 완전성을 보장하지 않는다.

## 공식 제공 경로

| 업종 | 공공데이터포털 | 공식 API 기본 경로 | 공식 전체 CSV |
| --- | --- | --- | --- |
| 일반음식점 | [15154916](https://www.data.go.kr/data/15154916/openapi.do) | `https://apis.data.go.kr/1741000/general_restaurants` | [전국 파일](https://file.localdata.go.kr/file/download/general_restaurants/info) |
| 미용업 | [15154918](https://www.data.go.kr/data/15154918/openapi.do) | `https://apis.data.go.kr/1741000/beauty_salons` | [전국 파일](https://file.localdata.go.kr/file/download/beauty_salons/info) |
| 노래연습장업 | [15155135](https://www.data.go.kr/data/15155135/openapi.do) | `https://apis.data.go.kr/1741000/karaoke_rooms` | [전국 파일](https://file.localdata.go.kr/file/download/karaoke_rooms/info) |

- 공식 무인증 조회 화면: `https://sample.localdata.go.kr/public/{slug}/info`
- 실제 공개 조회 요청: `https://sample.localdata.go.kr/public/call/{slug}/info?pageNo=1&numOfRows=10`
- 조회 화면은 페이지당 최대 10건으로 안내한다. 이번에는 업종마다 첫 페이지 한 번으로 총건수와 필드만 비교했고, 미리보기 페이지를 반복 수집하지 않았다.
- 전체 적재 검증에는 `file.localdata.go.kr/file/download/{slug}/info` 응답을 사용했다. 이번 3건은 인증키 없이 다운로드됐다. 이 사실이 무제한 요청이나 영구 제공을 보장하지 않는다.
- 공식 화면의 `file-download.js`에 있는 `/file/validate/download-count` 확인을 거쳐 다운로드했다. 403/429는 우회하지 않는다. HEAD 요청은 403이어서 파일 확인은 성공한 GET 응답 기준이다.
- 파일 경로 발견에는 공개 코드 검색을 단서로 사용했고, 근거와 실제 원본은 공식 도메인의 응답으로 확인했다. 외부 코드를 실행하지 않았다.
- 공식 카탈로그는 3종 모두 이용허락범위 제한 없음, 무료, 전국 취합 자료, EPSG:5174로 안내한다. 이용 조건은 수집 시점의 카탈로그 기록을 보관하고 추후 변경을 점검한다.
- 기존 `www.localdata.go.kr` 홈페이지 접근 실패/단순 응답과 파일·샘플 서버의 동작 여부를 구분한다. 홈페이지 문제만으로 전국 자료 제공 중단이라고 판단하지 않는다.

## 역사 자료와 재생 가능성

| 업종 | 관측한 최소 인허가일 | 관측한 최소 폐업일 | 주의 |
| --- | --- | --- | --- |
| 일반음식점 | 1900-05-31 | 1969-11-12 | 1900년대 날짜를 그대로 재생 시작점으로 잡지 않음 |
| 미용업 | 1900-07-13 | 1977-07-25 | 매우 오래된 날짜와 미래 폐업일 검토 필요 |
| 노래연습장업 | 1900-01-01 | 1992-05-23 | 기본값/오류 가능 날짜를 검토해야 함 |

과거 폐업은 최근 1년보다 훨씬 오래된 행도 실제로 제공된다. 따라서 참고 서비스의 최근 1년 상세 제공 정책을 원천 한계로 사용할 필요가 없다.
다만 최소 날짜가 오래됐다고 그 이후의 모든 연도·지역에 결손 없이 자료가 있다고 해석하지 않는다.
재생 시작 연도는 연도×지역×업종별 분포, 누락, 제도/수집 체계 변경을 추가 검토해 확정한다.

API 명세의 `/history`는 **2026-01-01부터 조회일 전일까지의 자료 기준일**을 지정하는 기능으로 안내된다.
이 기간은 원천 스냅샷 조회 범위다. CSV 행에 있는 1970~2020년대 인허가·폐업 날짜의 제공 범위와 다르다.
이번에는 인증키 기반 `/history` 실호출이나 날짜 경계/변경분 의미는 검증하지 않았다.
공개 샘플 및 CSV는 날짜가 `yyyy-MM-dd`와 `yyyyMMdd`로 혼재한다. API 명세의 `YYYYMMDD` 안내만 믿고 파싱 형식을 하나로 고정하면 안 된다.

현재 파일은 과거 사건 날짜를 포함한 최신 원부다. 과거의 이름·주소·좌표·휴업·재개업 상태 전체를 담은 변경 이력이라고 간주하지 않는다.
초기에는 인허가일/폐업일 기반 사건과 최신 알려진 위치에 의한 근사 재생을 제공하고, 향후 수집하는 버전 이력을 계속 보존한다.

## 실제 품질 문제와 스키마 영향

| 항목 | 일반음식점 | 미용업 | 노래연습장업 |
| --- | ---: | ---: | ---: |
| 존재하지 않는 인허가 날짜 | 4 | 1 | 1 |
| 존재하지 않는 폐업 날짜 | 0 | 4 | 0 |
| 조사일 이후 폐업 날짜 | 2 | 1 | 0 |
| 원천 상태명이 폐업인데 유효 폐업일 없음 | 561 | 61 | 222 |
| 1950년 이전 인허가 날짜 (검토 대상) | 81 | 14 | 2 |
| 관리번호만 기준으로 앞선 행과 중복된 추가 행 | 0 | 0 | 60,917 |
| 기관코드+관리번호 기준 중복 행 | 0 | 0 | 0 |
| CSV 열 수 | 39 | 37 | 50 |

- 예: 노래연습장 인허가일 `19950229`는 실제로 존재하지 않는 날짜다. 날짜 오류를 3월 1일로 자동 보정하지 않는다.
- 일반음식점은 2026-11-30, 미용업은 2026-11-23까지의 폐업일이 관측됐다. 조사일 기준 완료된 폐업 통계에서 제외/보류하고 원문을 보존해야 한다.
- 1950년 이전이라는 이유만으로 자동 삭제하지 않는다. 원천 기본값인지 실제 역사 자료인지 검토할 표식이다.
- 현재 상태는 폐업인데 날짜가 없는 행을 수집일에 폐업했다고 기록하지 않는다.
- 표의 날짜 오류를 이유로 파일 전체를 버리지 않는다. 사건별 집계 자격과 품질 사유를 기록한다.
- 원천 기관코드+관리번호의 중복과 누락 식별자는 3종 모두 0건이었다. **노래연습장업은 관리번호 단독으로는 유일하지 않았다.** 64,421행 중 관리번호의 서로 다른 값은 3,504개이며, 나머지 60,917행은 앞선 행의 관리번호와 겹쳤다. 이는 같은 기관 안의 중복을 뜻하지 않는다.
- 예: 관리번호 `CDFF3242052002000005`가 기관코드 `3000000`, `3010000` 양쪽에 있다. 따라서 업종+기관코드+관리번호를 원천 키의 필수 후보로 사용한다. 단독 관리번호 UNIQUE나 이름·주소 기반 병합은 적용하지 않는다. 이번 관측의 복합키 유일성이 향후 이관·통합 때까지 보장되는지는 추가 확인한다.
- 일반음식점/미용업은 주로 정상·폐업이지만 노래연습장에는 휴업, 취소/말소/만료/정지 계열 등 다양한 상태가 있다. 모든 업종에 `01=영업,03=폐업` 두 가지만 있는 것으로 구현하지 않는다.
- 노래연습장의 일부 정상 상태는 상세코드 `BBBB`와 빈 상세명이 있어 원천값 보존과 UNKNOWN 처리 경로가 필요하다.
- 취소·직권말소·이관은 실제 영업 종료/폐업과 구분하고, 근거 날짜가 없으면 폐업 사건을 생성하지 않는다.
- 기관 코드는 현재 공식 선택지와 대조해 매핑했다. 공식 상위 지역 그룹과 이름을 그대로 보관하며, 특정 시도 개수나 기존 코드를 하드코딩하지 않는다. 과거 지역 비교에는 경계·코드 버전이 필요하다.

파일 응답의 `Content-Type`은 `charset=UTF-8`이었지만 **실제 바이트는 CP949**로 정상 해독됐다.
따라서 다운로드 시 텍스트로 재저장하지 않고 바이트 그대로 보관한다. 스크립트는 헤더로 인코딩을 선택한 뒤 전체 파일을 엄격하게 디코딩했다.
파일 바이트 크기, SHA-256, 다운로드 시각, HTTP 길이 및 필드 목록도 남겼다. 쿠키·세션 식별자·CSP nonce는 추적 문서에 저장하지 않는다.

## 남긴 산출물과 재현

- [수집·검증 스크립트](../scripts/audit-national-permits.py): Python 3.11 이상, 표준 라이브러리만 사용.
- [공식 카탈로그 요약](data-samples/national/catalogs.json): 라이선스, API 경로/설명, 샘플 총건수/필드 목록.
- [공식 현재 기관 코드표](data-samples/national/municipalities.json): 현재 드롭다운 기준이며 과거 코드 전체 사전이 아님.
- [일반음식점 검사](data-samples/national/general_restaurants.quality.json), [미용업 검사](data-samples/national/beauty_salons.quality.json), [노래연습장 검사](data-samples/national/karaoke_rooms.quality.json): 전체 행 검사, 날짜/상태/지역 분포, 원본 해시.
- 같은 디렉터리의 업종별 `*.sample.json`: 필요한 공통 필드만 추린 각 20건. 전화번호/종사자/시설 상세는 저장하지 않았다. 좌표 누락·과거 폐업 등 조건별 앞 5건을 뽑은 검증 샘플이며 통계 표본이 아니다.
- 전체 파일은 `data/national-audit/{slug}.csv`, 다운로드 기록은 `*.download.json`이다. 원본을 Git에 추가하지 않는다.

```powershell
# 이미 받은 원본 전량 재검사 (네트워크/DB 불필요)
python scripts/audit-national-permits.py

# 원본이 없을 때만 공식 서버에서 내려받고 검사
python scripts/audit-national-permits.py --download

# 한 업종만 검사
python scripts/audit-national-permits.py --slug beauty_salons
```

`--download`는 기존 CSV를 덮어쓰지 않는다. 다른 날짜의 스냅샷을 받으려면 `--data-dir`과 `--output-dir`을 별도 경로로 지정한다.
한 파일 최대 1 GiB 제한과 `.part` 임시 파일을 사용하며, 전체 다운로드 후 공개한다. 응답 길이와 실제 바이트 수가 다르면 실패 처리한다.
현재 카탈로그/코드표 기록은 조사 시점 산출물이며 CSV 검증 스크립트가 자동으로 갱신하지 않는다.

## 다음 구현에 확정할 내용

1. 3종을 받는 공통 원천 행 모델 + 업종/상태 어댑터. CSV의 한글 헤더와 API의 영문 필드명을 명시적으로 대응한다.
2. 인허가 ID, 관측 버전, 인허가/폐업 사건, 수집 실행 테이블부터 Flyway로 도입한다.
3. 미래/오류 날짜 및 좌표 없는 행을 품질 코드로 관리하고 집계·지도 제외 건수를 분리한다.
4. 최신 원부의 과거 사건 날짜로 초기 재생 기반을 만든 뒤 이후 스냅샷을 변경 이력으로 축적한다.
5. 전국 원본을 지금의 50건용 JPA 단건 반복 적재기로 그대로 밀어 넣지 않는다. staging과 청크/배치 적재, 재개 위치, 원본 행 수 대사를 구현한다.
6. 이력 API 실검증은 공공데이터포털 인증키가 확보되면 진행한다. 첫 전체 적재용 CSV 확보에는 이번에 인증키가 필요하지 않았다.

DB 설계 배경은 [개·폐업 변화 지도 설계안](commercial-area-timeline-data-design.md)을 따른다. 이번 검증으로 3개 업종 전국 CSV 확보와 과거 폐업 포함은 확인했으며, 전국 좌표 정확도/과거 완전성/원격 DB 대량 적재/정기 갱신 완료를 주장하지 않는다.
